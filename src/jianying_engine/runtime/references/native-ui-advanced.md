# 高级原生界面操作

2026-10-07后的调用状态：本参考保留为研究资料；[暂存清单](capabilities.md#parked) 中无法后台完成的效果不自动调用这些UI步骤。仅在用户另行明确要求研究、重新验证或单独前台复现对应效果时使用。今天已有UI复现证据保存在工作区，不等于后台接入成功。

用于单独兼容测试、明确界面补做和保存重开。已接入动态矩形、全时长/局部视频文字音频复合、外层rotation/up_left及 [2026-10-08扩展](capabilities.md)，日常直接写计划；其他角点、多级与效果轨复合仍有缺口。本页下表保留2026-10-06历史样本范围，当前接口看扩展与暂存清单，不当作自动占用前台的授权。导出和最终视听由用户负责。

## 能力与证据

本机测试日期：2026-10-06；Windows 剪映专业版 11.5.0.14471。五秒、1080×1920、30fps，两条同源视频轨，前景静音。结果不推广为其他版本或所有素材都兼容。

| 方法 | 实际验证 | 未覆盖范围 |
|---|---|---|
| 动态蒙版 | UI 位置关键帧；正式后台生成矩形 X/Y/旋转，非零源入点；窗口移动及 0→30° 旋转、数值插值、复合内部和保存重开 | speed≠1 只有结构回归；大小、羽化、其他形状、文字蒙版和跟踪动画未验证 |
| 复合片段 | 两条视频轨创建原生子草稿；外层单片段，双击进入仍有原始两轨；保存重开可再进入 | 视频与字幕/特效混合复合、多级嵌套、组混合及任意组级效果未验证 |
| 四角变形 | 外层复合的左上角原生偏移关键帧；中间值与画面变形、播放、保存重开 | 其余三角动画、真实三维摄像机/曲面贴图、导出表现未验证 |

时间码末项为帧，按工程 fps 换算；关键帧位置取当前片段局部时间，后台再映射到源时间。

原生面板整数取整可能与计划浮点值存在差异；保存重开须分别核对参数、画面与可编辑图层，不宣称像素完全一致。

后台蒙版关键帧 time_offset 是源时间微秒：`source_in + 局部秒数 * speed`。直接写局部时间会使素材中段的窗口初始就跳到终点。生成器已自动换算；计划仍填写局部秒数。三轨与两个互不相交的复合组通过结构回读，界面保存重开实测为两轨单组。

## 基础草稿与界面补做衔接

已核实的原生序列化中，复合外层视频素材 `corner_pin` 包含 `enable_corner_pin=true`、原始四角归一化坐标及唯一 id；片段 `common_keyframes` 的 `KFTypeCornerPinUpLeft` 存储二维 values。已纳入后台生成及参数回读，支持首点0、严格递增局部时间和线性插值。视频运动与蒙版都按源时间写入，不能重复临时 monkey patch。下面 UI 步骤只在明确开展兼容测试或用户指定界面操作时采用。

1. 按成片目的设计开始、到位和释放构图。需要只移动窗口时选择蒙版位置关键帧；多个图层作为整体变形时选择复合后角点变形。平面旋转不能充当角点透视。
2. 正常 validate/build/publish 基础草稿，预先保留所需原素材、多轨、源范围、原声和基础变换。只组合需要共同处理的图层和时间段，独立背景留在组外。
3. 在计划 `notes` 说明高级原生操作，并在任务目录创建 `原生补做.md`：记录实际草稿绝对路径、目标轨道/素材及源范围、外层/内部范围、局部关键帧时间、起止构图、待执行步骤。这是界面操作记录，不是生成器输入；不向 `jianying_tasks` 添加 dynamic_mask/compound/perspective 等未知枚举。
4. 使用当前环境的 `computer-use` Skill 控制剪映。Windows 操作通过其 `node_repl + @oai/sky` API；操作前读取该 Skill 及要求的指导文件。先选择正确窗口，再观察、单步操作、刷新；按截图现状定位，不复制样例坐标。工具不可用或用户限定后台时，留下具体待办，并说明核心效果尚未完成。
5. 需要补做的操作完成后，针对相关原生参数和预览做局部核验，再保存、关闭编辑页、重开检查关键帧及复合内部。此核验属于补做剪辑，不代替用户最终视听和导出。对新建草稿执行；局部修改使用用户指定最新稿的独立副本，保留原稿。
6. 完成后在 `原生补做.md` 记录各项状态（待执行/已执行/已验证）、面板读数、重开结果及异常；更新 `剪辑交付.md` 和 `原生效果.md`，关联最终草稿路径。生成器的 `verification.json` 仅证明基础草稿，不能自动代表补做后的验证。任一必要补做仍待执行时，交付状态注明相应剪辑缺口，不能沿用 build 的 complete 作为全工程结论。

界面保存后草稿与 `edit-plan.json` 不再完全等价：计划只能重建基础层，高级原生操作以保存的草稿和补做记录为准。关闭编辑页后复制完整最终草稿到本版工作区归档，保留原素材引用路径；不能仅备份计划，也不能重新 build/publish 覆盖补做成果。

人物抠像界面研究先按[前景分离判断](green-screen.md#原生执行顺序)区分可见主体漏选与真实遮挡；抠像不能生成被挡住的像素。只有实际质量审阅合格后才用[缓存准入工具](capabilities.md#matting)注册已有产物。失败样本保存、关闭编辑页并归档，注明质量拒绝；未实际重开时如实写未验证，不靠旧样本继承。

## 人物抠像界面计算与后台复用

这是一条已验证的条件流程：原生界面新计算/补选→保存关闭重开→完整归档与质量审阅→admit-matting注册→正式后台生成。需要用户明确授权界面抠像或研究；普通任务默认后台，不自动开启界面，也不把UI计算写成后台新计算。当前实测为复杂背景游戏近景、1280×720/60fps、静音速度1；真人、任意动作/遮挡和未测组合不继承质量。

1. 从实际画面选源范围，优先无重要前景遮挡、主体完整的片段；独立基础稿保留原片和底层对照背景，不复制旧mask，不修改认可稿。按前述发布流程打开并核标题。
2. 画面→抠像→自定义抠像，原生智能画笔补入脸、头发、肩部与衣饰。大小按区域判断，不能照搬坐标；每笔后等待实际选区结果再决定下一笔，即时截图未变化不证明无效。必要区域先保完整，再处理背景；不为发梢少量残色持续细修。应用效果后核实际合成，cyan编辑叠色不算完成。
3. 核起中尾及动作/变化候选；大洞、缺脸/肩或真实遮挡导致的空缺均拒绝。原生羽化/边缘缩放按实际面板核对，不能藏孔洞。保存关闭重开，检查画面和自定义工具/参数，关闭编辑页后完整归档，不重build覆盖UI稿、不解密改写。
4. 把选定custom ID对应的自定义分支完整复制到Skill外稳定缓存根。按[准入契约](capabilities.md#matting)核源时间范围、帧数/负载与文件身份，保存真实审阅、证据和身份摘要，运行admit-matting。只在确实通过主体审阅时填合格状态；工具核身份不代替视觉判断。
5. 用生成manifest/哈希写clips.matting_cache，按受限子集正式validate/build/verify/publish；黑灰白底分别检查新缓存的原生静帧，必要背景再验。归档UI稿保留原生笔刷编辑状态，后台新稿保留原生缓存绑定；新后台稿的UI编辑/重开另验，不能继承归档稿结论。原片、缓存、manifest等引用须保留；完整视听和导出仍由用户完成。

本流程解决已授权场景中的人物分离与后台复用，不解决纯后台新算法提交。只开放实际通过的源范围，遮罩数齐全不意味着所有素材可用；出现失败时按[前景分离判断](green-screen.md#原生执行顺序)换范围或拒绝，不扩大自动计算能力。

## 动态蒙版位置

- 选中目标上层视频，打开“画面 → 蒙版”，确认启用并选择所需形状；先核对静态窗口的实际位置、尺寸、羽化和圆角。
- 起点定位后，在蒙版参数的“位置”行加入关键帧，调整蒙版中心；终点重新定位并加入/确认位置关键帧。只有移动窗口时保持片段基础变换不动。
- 数值输入只有提交并重新读取后才算成功；文本暂时显示不证明落盘。输入失败时可在预览中拖动蒙版控件，再读面板数值。不要误拖素材变换框。
- 核对首尾、中间值和窗口实际移动；保存重开后再读。只验证位置不意味着大小/羽化或自动跟踪已完成。

旧版静态 mask 写在 materials.masks，样例首次打开未启用，UI 勾选后尺寸/羽化未保持原计划。正式生成器已将矩形迁移到 materials.common_mask，补充 constant_material_id 和 enable_video_mask；v5 已实测自动启用及保存重开。其他形状继续保留实验边界，当前任务仍需局部核对。

## 复合片段

- 在正确时间线选中目标视频层，右键选择“新建复合片段（子草稿）”；本机快捷键为 Alt+G。Ctrl+A 只适合全选恰好都是目标图层的独立测试工程，正式工程使用明确范围选择。
- 核对外层变为一个复合片段、范围及声音未意外改变。双击进入内部，确认所需图层、源范围、蒙版与关键帧仍在；通过内部时间线返回箭头回外层。
- 整体角点变形放外层，局部蒙版留内部。内部时间码与外层起点可能不同，按局部时间校对，不能套用主时间线秒数。
- 不用中间导出重导代替原生复合；文字/特效复合未在这次样例验证，实际使用时单独核对原生可编辑性与作用范围。

## 四角变形与预览异常

- 选择目标片段或外层复合，进入“画面 → 基础 → 变形”，启用并打开“拖拽变形”。面板包含四角独立 X/Y 行和关键帧入口。
- 在预览中拖动对应角点，核对角点偏移读数；在起止时间确认角点行关键帧。检查中间帧插值以及画面内容确实按四边形变化，不能仅看编辑框形状。
- 变形、混合和描边区域相邻，操作后核对勾选项；测试曾误勾描边，但样式仍为“无”。不要把非必要勾选带入正式工程。
- 实测进入复合内部再返回外层后，角点读数与编辑框正常，但内容一度按矩形显示，播放未恢复；关闭重开后斜四边形渲染恢复。遇到同样现象先保存并重开一次再检查。不得断言根因是缓存，不凭编辑框宣称渲染正常；重开仍异常时保留草稿/读数和具体缺口，停止重复无依据重试。导出是否受影响尚无证据。

## 交付措辞

2026-10-08普通编辑器新素材研究：3秒跟踪覆盖180帧，2.4秒处文字跟随；智能人物抠像损失部分手臂/飘带，自定义画笔补回手臂却引入背景残片，不能据此准入漫剪自动抠像。3秒新计算倒放的五帧与逆序原素材匹配，缓存音频亦倒放，并保存重开；这些都是普通编辑器执行证据，未取得后台算法提交/任务ID/取消契约。Node/Bun原生renderer销毁后均仍不自然退出，监督器超时终止自己的实验子进程不能称为修复。

声音研究已核对原生降噪、响度及仅保留人声的实际输出；背景声选项不可用。分离产生上传/下载中间文件，不能宣称纯本地。独立audio实时降噪与受限-23LUFS响度参数已正式后台接入，范围与WAV/MP3精度限制见扩展格式；其余声音任务仍暂存。参数、局部预览、输出分析与最终试听分别记录，禁止按旧缓存或波形数值扩大能力。

“已通过界面补做并保存重开验证”只适用于本次真实执行且通过核对的操作；此前样例成功仅能支持选用此路径。后台自动生成、界面已执行、当前预览已验证、保存重开已验证、用户最终检查/导出分别说明。不把这些能力扩大到智能抠像、跟踪、曲线变速或三维摄像机。
