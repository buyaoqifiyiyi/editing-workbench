# 剪辑修订与表达判断

用于用户反馈文案、画面、节奏或声音不足时。先按反馈定位实际问题与认可范围，用已有素材分析和计划 notes 记录修改判断；不新增逐项确认或固定评分表。

## 反馈如何转成操作

| 反馈 | 先查什么 | 如何修改 |
|---|---|---|
| 文案空泛 | 句子对应的可见动作、物件、情绪与后文呼应；对白/引文/作者文案的身份 | 写具体意味；删去无作用对仗和未经核实的剧情，先改内容再安排动效 |
| 文字突兀 | 场景留白、视线、方向、阅读构图、动态背景对比与层序 | 设计锚点、到位、停留和退场；加动画不能自动解决语义或排版问题 |
| 文案通过但技术展示不足 | 原有图层是否形成可辨认的起止变化 | 保留明确认可的文字与必要阅读时间，从原素材重设揭示、分区归位或构图展开，强变化后交还完整动作 |
| 太乱或看不清 | 原片自带运动、循环动画、叠层、关键帧与实际作用范围 | 定位干扰源，减少无目的持续刺激；组内同步，背景按职责独立运动，不只统一降低所有参数 |
| 太长或没有推进 | 重复动作、无新信息停留、原片内切点与乐句 | 从原素材重新筛选有效事件；不靠全片加速、固定秒数或延长片长展示更多技巧 |
| 不要重复画面 | 源范围重叠、同一镜头的不同裁区/变速、原片自带回放 | 按 [镜头去重](general-editing.md#镜头使用与去重) 区分前后重放与同刻合成；用不同镜头回应意象，不能拿效果包装当新画面 |
| 听感差或力量不足 | 配乐源段、速度、乐句、碰撞起音、重复声音路径与峰值 | 保留完整语义和动作因果，重排原声与BGM避让；没试听就保留未核实状态 |

反馈说明体验受到影响，不一定证明某个参数失效。先区分查实原因、合理推断和未定位问题；整体认可不代表文案、混音和各项兼容性都合格。

## 短段比较与反馈积累

制作与修订回到[创作判断流程](../guides/planning.md#创作判断流程)定位问题。先核对选段与关系，再调整顺序、切点、声音和表现；只复查受影响段落及衔接，保留用户已认可的部分。

存在关键不确定性时，从当前项目选能暴露问题的一段，保留足够的前后文。用相同原素材、BGM版本、表达目标与输出条件比较两种具体剪法，例如“接动作还是留反应”“这里切镜还是保持动作”“效果是否改善连接”。明确改变的变量和预期观看差异；不用一边换音乐、一边增加效果后把整体差异归因于某一种技巧，也不默认多做整部成片。

在项目已有分析或说明中记录实际片段路径/时间范围、输入版本、比较的做法、观察到的效果、用户反馈与仍未验项目。先判断注意力是否顺利交接、动作/关系是否看清、情绪是否发展、声音是否推动或干扰、表现是否符合目标；具体偏好可以不同，不设“审美总分”、效果数或模型自评通过线。

静帧仅支持构图与层次判断；时序画面支持所采样的运动，听感与完整连续体验需要相应实际输出和观看。没有可用媒体或播放条件时，把比较保留为待验证方案；写了两种剪法不能登记为完成A/B观片。后台构建或导出成功只证明其技术层级。

学习用户审美时，把认可与不认可的片段和理由成对保存在项目原位，区分整体风格、具体连接、文字和声音反馈。下一次同类任务先取适用的已确认例子，比较素材条件和目标，抽取“在什么前提下，哪种做法带来了什么结果”。孤立的“喜欢某特效”不提升成所有作品的配方，来源或评价缺失时不编案例。普通剪辑只记录当前项目；通用经验进入引擎仍按明确授权的[维护流程](../guides/maintenance.md)处理，不自动写Obsidian或改Skill。

## 分层、揭示与共同运动

复杂表现交给具体画面事件：细节被看见、人物亮相、追逐、物件与人物关系、接触爆发或情绪回落。每层承担观看任务，明确开始、到位、可读停留及释放，不按轨道或关键点数量评价。

同源分区在合拢时核对源时钟 `source_in + (T-start)*speed` 以及 fit、缩放、位置和旋转。轨道起点错开时同步调整源入点；只延迟运动而未延迟素材时，不重复改变源时钟。窗口中心动画与素材位移动画分别安排。

边框、文字和面板应成组运动时，先在像素坐标中计算共同中心，再转回各轴单位；采样中途插值，不能只核对首尾。缩放关键帧的当前绝对目标语义见 [计划格式](plan-format.md)。矩形窗口携带原背景，不等于人物抠像；二维角点变化不等于三维摄像机；密集线性点不等于原生缓动。

## 修订与验证

整体优化默认从原素材建立新计划；分析、来源和认可方向可复用，旧时间轴不默认继承。用户指定局部修改时按指定范围，以最新稿的独立副本为依据，不用旧计划覆盖手工工程。

登记、黑封面、打开、参数回读和播放分开排查；已有登记但封面异常时不重复发布或修改全局索引。结构、插值几何、用户整体认可和真实渲染是不同证据，项目分别记录。用户说“验收通过”时记录为用户验收反馈，同时保留其追加限制；未完成的人声分离、歌词覆盖或具体动态验证不会自动变为通过，也不推断已导出。当前能力查 [能力状态](capabilities.md)，本页不另立能力表。
