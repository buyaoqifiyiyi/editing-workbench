# 能力状态与准入边界

本页是剪辑工作台内部剪映后端能力状态的唯一主表：哪些能力可进生产、可用到什么子集、写哪个计划字段、不满足时用什么替代。剪映仍在持续适配，未完成项继续按本表和外部固定缺口台账推进；达芬奇并行接入不替代或注销剪映接口。字段格式、单位与校验规则见 [计划格式](plan-format.md)；研究与逐项接入流程见 [逐项接入](progressive-integration.md)，仅在用户要求研究时读取。

适用环境：Skill 创建时本机注册表为 Windows 剪映专业版 `11.5.0.14471`，配合当前 `editor.py` 与固定 `pyJianYingDraft==0.3.0`。每次任务用 `doctor` 重新读取；注册表版本不证明运行中版本，也不证明工程兼容。环境、代码或模板指纹变化后重新检验，不沿用旧环境的通过状态，不手工改 passed。

## 达芬奇主剪辑接入子集（2026-10-20，当前路线）

工作台当轮选择达芬奇时使用[resolve-workflow](resolve-workflow.md)和独立`backend=resolve`计划；该选择不替换其他会话后端。受限范围为Resolve 21.1.1、本机既有脚本连接、30fps视频顺序剪切、静态缩放/位置/顺时针旋转/透明度、原声及独立立体声配乐增益、纯文字字幕轨、保存关闭重开、DRP与NVIDIA H.264/AAC输出。CLI/MCP共用白名单；不复用剪映原生效果字段。已有用户工程阻断、跨进程宿主锁、输出防覆盖、代码/计划/媒体变化拒绝执行；源码检查和离线自检不代替原生输出验收。

2026-10-23新增有界子集：`captions[].text/start/duration`支持中文、单/双行、跨剪辑点，SRT入原生字幕轨并烧录导出；文字与起止帧经保存重开读回，样式沿用轨道默认，不接字体/位置/字词动画。组合选择AE时，已成功渲染的有界镜头经`resolve-workflow return-ae`重新校验后替换选定片段，保留其他镜头、主配乐和字幕，归零入点并避免重复增益/变换；AEP保留可编辑参数，Resolve接收渲染视频。

达芬奇关键帧、多层视频、Fusion/AI、调色、变速，及AE指南列明有界子集之外的复杂镜头往返仍未准入。30fps平均帧率探测不认证CFR，prepare及执行前后会检查视频全部帧PTS，初期源限600秒，拒绝VFR/不足帧/时间戳断裂；长源先另存规范化选区，不覆盖原片。实际项目仍分开记录参数读回、保存重开、声画内容、完整视听与导出证据。本机PR已卸载，AE与Creative Cloud保留；此接入不抵销下文剪映固定功能族缺口。

## PR＋AE迁移子集（2026-10-20，历史路线与可选AE模块）

AE当前可按[独立AE分支](adobe-workflow.md#独立ae调用)使用既有`backend=pr-ae`有界计划，通过`run-ae`制作原生文字、变换与线性运动并输出AEP和无损镜头AVI，不要求PR或主剪辑后端。PR历史XML交接仍保留但当前未开放选择，独立配乐原本由主时间轴混合。剪映参数与准入不能直接当作Adobe能力；复杂文字动画、自动人物分割/跟踪、下文凸多边形之外的遮罩、插件效果和Dynamic Link尚未准入。

2026-10-23继续开放整层文字子集：AE的`captions[].scale/opacity/motion`支持文字层位置、缩放和透明度线性关键帧，文字时钟跨镜头连续求值；保存前/重开后文字内容、字号/颜色、出入点及原生关键帧逐项对照计划。仅整层线性动画，不包含逐字动画器、表达式或缓动预设；不据此结清剪映动态文字等其他功能族。具体参数见[AE动态文字](adobe-workflow.md#可编辑整层动态文字)。

2026-10-23新增前景遮罩接口：`clips[].foreground_mask`接受3–32个源视频原像素坐标顶点组成的严格凸多边形、0–100源像素羽化（默认0）与布尔反转（默认false）。前景复制原源层并继承变换/运动，静音后放在文字之上；有遮罩的源层基础及关键帧透明度必须恒为1。AEP保留ADD遮罩与可编辑图层，`ae-layer-readback.json`对照保存前/重开后层序、源时钟、音频及遮罩参数；原生保存重开、渲染遮挡/羽化/运动和声音需按本轮包外记录分别验收。该接口不自动分割或跟踪人物，不接Bezier、遮罩动画或多遮罩，也不据此结清剪映固定功能族。完整契约见[AE前景多边形遮罩](adobe-workflow.md#可编辑前景多边形遮罩)。

隔离的2秒320×180/30fps合成样本已完成AE项目创建/重开/实际渲染，及PR原生导入、保存和H.264导出；逐帧检查切点、文字和运动，并检测左右声道分离及音量。PR音频采用已实测的成对立体声轨结构，避免XML往返丢失声像。连续人工视听、复杂工程和跨机兼容未验。AE启动曾需用户处理崩溃恢复窗口，PR导入/保存/导出仍需原生界面操作，不能称全无人值守。安装完整性异常与功能验收分开记录；本子集不抵销既有剪映固定功能族缺口。

- 项目结果、测试参数和逐轮统计保存在外部维护记录。

## 证据层级

证据分六层记录：计划/结构、原生参数回读、指定时刻原生静帧、UI 编辑保存重开、完整视听、导出。后一层不能从前一层推得；准入只覆盖实际验证过的输入、组合与环境。

- `verification.json` 的完成状态表示剪辑结构与参数已落实，不表示资源呈现或完整质量验收。
- 预览报告通过只表示收帧协议通过。要声明画面通过，还须核对素材、源时间、裁区、层序和文字像素。
- 研究静帧不自动更新生产 verification，也不成为每次交付的新门槛。
- 各子集按自己的正式 build、结构回读、拒绝边界与发布路径准入。一项的 UI 保存重开结论不能套给其他字段；研究工程的整体质量不能转给新项目。新项目的资源、渲染、UI 与听感状态分别记录。
- 原生静帧预览为 320×180，只证明离散时刻，不能称为高清质量、连续播放或导出通过。

## 后端与发布

用 [pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft) 固定版 `0.3.0` 的公开 API 构建基础草稿，再按本机 11.5 明文结构写入矩形动态蒙版、复合等扩展。保留原素材和参数；不外部烘焙效果，不改写官方程序。

- 上游文档列举的是 10.8 的部分生成能力；Skill 创建时未验证 11.5 的 UI 打开、保存重开和视听结果。
- 上游自动导出依赖 uiautomation，会置顶剪映、移动光标，也不支持新版本。本 Skill 不调用该控制器，也不用 FFmpeg 粗略重渲染整个工程冒充原生导出。
- 新版已有草稿可能不是明文 JSON；上游只提供自定义加载器接口，不带解密实现。本 Skill 只构建新草稿，不读取或改写用户的加密已有工程。后台在 publish 与 native-preview 两个入口由 `scripts/editor.py` 的 `draft_state` / `require_plaintext_draft` 按字节判定明文/加密/损坏/缺失后具名拒绝（不解密、不覆盖、不修），自检 `scripts/draft_state_self_check.py`。
- 剪映保存我方草稿时会改写它：正文变密文，同时生成 `Timelines\<UUID>\` 镜像（`draft_content.json` / `.bak` / `template-2.tmp` 三类与根层逐字节相同），顶层 `fps`、`name`、`cover`、`create_time`、`update_time`、`source` 等与整块 `config` 被删除、材料按引用去重并为每个片段补齐运行期材料、绝对路径被改写为 `##_draftpath_placeholder_*_##`，并写入 `platform.mac_address` / `device_id` / `os_version` 等本机指纹。只写根层足以让剪映打开（我方草稿没有 `Timelines\` 也能被打开并保存）；保存过的版本带指纹，不作对外交付。逐键对照与证据见 `Skill维护层\来源\草稿存储权威位置-20261016\experiment-20261016-first-save.md`（对照工具 `Tools\jianying-11.6-contract\draft_roundtrip_diff.py`，只读）。
- `publish` 读取 `Config/globalSetting` 的 `currentCustomDraftPath`，把完整新版本复制到实际草稿目录，再等待剪映原生登记。C 盘 `Projects/com.lveditor.draft/root_meta_info.json` 可能只是首页索引位置，不是运行时扫描目录。指定其他目录会被拒绝；离线归档用 `--offline-copy`。脚本不改全局索引、不重启剪映；登记超时返回 unverified。已核实该版本按真实配置目录自动发现新稿，新任务仍核对自己的登记结果。
- 剪映的草稿监视器只登记它运行期间观察到的新建目录：在剪映未运行时放进去的文件夹，之后即使重启剪映也不会补登记，首页因此看不到它（实测：16:27 复制、16:46 重启后索引仍无此稿）。补救用 `scripts/editor.py refresh-registration --draft <配置草稿根直下的目录>`：先读原生索引，已登记就原样返回、一个文件都不碰；未登记则确认剪映正在运行后，把该目录复制到旁路、逐文件校验、删除、等 8 秒、再复制回原位，用一次真实的新建事件触发登记（实测 5 秒内出现登记事件）。往返前后逐文件 SHA256 必须一致，不一致就从旁路恢复并报错；不写全局索引、不重启剪映、不改动加密草稿的内容（备份的是目标目录自己的当前内容）。剪映未运行、目录不在配置草稿根直下、目录不存在或缺少 `draft_meta_info.json` 都被拒绝。自检 `scripts/refresh_registration_self_check.py`。
- 被剪映接管过的草稿副本可能从此对本账户**完全不可访问**（实测 2026-10-17：`运行数据` 下 18 个 `draft*` 目录里，被应用打开/接管过的那 2 个，列出、读取、删除、改名与读 ACL 全被拒，`Get-Item` 仍报 Directory、`os.stat` 仍报 `0o40777`；安全描述符读不出来，**成因未证实，不要据此推断是哪条权限**）。所以工作区里自留的草稿副本既不是交付物、也不是长期可读的证据：交付物是配置草稿根里那份，证据请另存（计划、报告、stdout、静帧）。不要为了取回它去改权限、改所有权或提权；验收脚本要能重复运行，就别把输出目录写死成一个可能变砖的名字。
- 工程结构里有转场、字体或特效资源，不等于当前机器已下载、有权限或能呈现。
- 层序：显式 `layer_order` 与复合通过 `free_render_index_mode_on=true`、`render_index_track_mode_on=false` 落实片段索引层序，主稿、嵌入稿与发布 sidecar 分别回读。模式关闭时文字仍会盖住前景视频，只回读轨序不够。该修复已用前景矩形遮挡文字的独立静帧核验。
- 关键帧和资源从实际引用回读。结构支持不证明资源下载、当前画面或编辑保存重开。
- 本机 11.5.0.14471 的独立 UI 测试验证了动态矩形蒙版、复合片段和左上角变形的编辑、插值与保存重开，后台按其明文结构写入。组合返回曾出现一次预览刷新异常；导出未核实；日常生成不依赖 UI 补做。

分工：Skill 完成素材分析、剪辑决策、原生草稿生成、计划校验与结构/参数回读；用户明确要求时按 UI 路径补做必要界面操作并局部核验；用户完成最终检查与导出。局部测试结果按实际范围保留。用户最终步骤未执行，不判定剪辑未完成；未做的必要界面操作也不能藏进这个分工。

自检范围：

- 合成素材验证场景切点与抽帧、音轨提取、视频/图片/音频轨、变速、关键帧、字幕、源范围越界/同轨重叠/未知字段拒绝，以及禁止覆盖现有输出。
- `native_self_check.py` 另验原生资源引用、参数、独立效果轨、动画时间、原素材哈希保留、错误参数拒绝及待办状态。合成源素材由 FFmpeg 创建，只用于测试，不预渲染剪映特效。
- `extensions_self_check.py --out 新目录 --video 现有3840×2160且至少29秒原片 --music 至少8秒音频` 覆盖前一批扩展，含资源身份篡改与四类缓存缺失拒绝；不改原素材、不渲染特效。
- 合成素材只证明工具调用与生成结构，不能替代 11.5 上的真实打开和成片试听。

参考视频分析：自动探测不含语义识别、OCR、语音转写或音乐节拍检测。Agent 用实际可用的视觉和音频能力判断并报告缺失能力；不必为执行本 Skill 安装全部分析框架。

## 原生缓动 smoothstep

状态：以下三个子集已准入，只接受 `motion_easing="smoothstep"`；省略时保持线性 Line，不静默附加非线性曲线。计划字段见 [计划格式 · 画面关键帧与缓动](plan-format.md#画面关键帧与缓动) 和 [captions](plan-format.md#captions字幕和标题)。复合外层的缓动见 [局部复合](#composite)。

| 对象 | 可用子集 | 额外拒绝 |
|---|---|---|
| 图片 | 恰好两个 position_x 点；source_in=0、speed=1 | 图片垂直缓动 |
| 视频 | speed=1；恰好两个同轴 position_x 或 position_y 点；允许合法非零源入点与时间轴起点，保留已有声音与音量参数；静态 fit/transform 可用 | 非 1 速度、曲线变速、片段效果/滤镜/动画/混合/色键/背景/蒙版/调色、转场、重叠独立效果/滤镜 |
| 文字 `captions[]` | 非复合；恰好两个 position_x 点；默认字体及已准入缓存字体；局部时间，不加 caption.start | animations、非空 transform、text_curve、`style.vertical=true`；文字垂直缓动 |

共同规则：首点 time=0，末点严格早于片段（或文字）duration；位移单位同画面关键帧，正负方向均可；垂直正值向上，按半画布高度换算，不与 position_x 混用。拒绝其他属性、多点、任意手柄、图表预设及复合内缓动。已审阅 `matting_cache` 的单轴运动按 [人物遮罩绑定](#matting) 的例外子集使用，不解除几何 mask 等限制。曲线变速是另一个契约，不能由位置曲线推定。

实现：原安装前端的曲线枚举与草稿序列化位于 ai-creation~5/~6/~13 模块；原 XML 参考注明 easing/ease 参数被忽略，写入它们不能宣称曲线有效。生成器直接写原生 common_keyframes：

- 首点 CurveOut，right_control=(Δ微秒/3, 0)；末点 CurveIn，left_control=(−Δ微秒/3, 0)；其余手柄为 0，graphID 为空。渲染进度对应 3u²−2u³。
- Δ 按实际序列化的源时间差计算：先分别把两端舍入到微秒，再求差，避免非零源入点的舍入偏差。
- 控制点 X 是相对时间微秒，Y 是相对参数值，不能混成画布坐标。
- validate/build/verify/publish/交付统一核对类型、手柄、时间和值；未请求曲线的普通关键帧也拒绝非线性手柄篡改。

已有证据：

- 图片水平：与线性对照比较实际静帧位置，并改变时长、位移范围和方向复验；保存重开与终点数值编辑已核，手柄与 UUID 保持。原生保存可能省略 time_offset=0 和空 graphID，回读按默认值规范化。其他曲线枚举不能由相似结果自动准入。
- 视频：正反向、非零源入点/时间轴起点、带声输入的源范围与音量保留、静态放大，正式生成链有独立原生位置/帧号对照。垂直另核源时间手柄、正反向/静止、非零源入点/起点和静态放大。
- 文字：正反向、非零 start 与停读状态；文字外框位移经线性/缓动对照，并在改变文字、字号、幅度后正式重建复验。其余基础 style 沿既有接口保留，不代表所有 style 与缓动的组合都已独立呈现验证。

未验证：手柄 UI 拖动、视频 UI 编辑/保存重开、文字 UI 曲线编辑/保存重开、连续播放、导出；声音参数保留不等于听检通过。视频与文字不继承图片的 UI 证据。

使用：

- 起止缓动适合从静止出发、到位后停留的画面重构。同向动作交接要检查切点速度，不能把两端减速当连续动作匹配。
- 额外平移或放大先和原构图比较，留足边缘余量，检查脸、手和重要背景；实验幅度不是默认审美配方。
- 文字检查完整字形外框、安全区与到位后的阅读时间。

复验：`scripts/motion_easing_self_check.py --out 新目录 --plan 含已准入图片/视频字段的计划`，覆盖正反向新建/离线发布/交付回读，曲线类型、时值手柄、图表引用、点数与时间值篡改拒绝，非法对象/属性/边界/组合拒绝及输入不变；另覆盖文字局部时间/字体/非法组合，以及组水平/垂直位移和受限等比缩放的正式生成、sidecar、属性/曲线/时间/值篡改拒绝。

替代：其他属性、多点或任意曲线用多点线性关键帧近似，并注明不等同教程的三次方缓出。

状态：全时长与局部 video/text/audio 复合已准入；外层支持 rotation、受限两点线性位移/等比缩放、受限水平 smoothstep 和 [左上角透视](#perspective)。计划字段见 [计划格式 · composites](plan-format.md#composites复合)。

| 外层运动 | 取值 | 组内限制 |
|---|---|---|

| position_x 或 position_y 线性，恰好两点 | −1 到 1；垂直正值向上、按半画布高度换算 | 仅 speed=1 普通媒体、静态 transform 与静态文字 |
| uniform_scale 线性，恰好两点 | 0.6 到 1.2；生成等值 ScaleX/ScaleY，围绕画布中心同时改变组内位置和大小，1 恢复既定布局 | 同上 |
| position_x smoothstep，恰好两点 | ±0.35；须显式 start/duration | 恰好一张 contain 图片与一段已准入缓存字体的 BMP 单行静态白字，两轨各一个片段且完整覆盖组区间；图片与文字 transform 为空；文字 border/bold=false，style 只可省略或 auto_wrapping=false |

- 位移/缩放组拒绝 audio、内层运动、片段效果/滤镜/动画/蒙版/调色/色键/背景/混合/转场，以及文字动画与弯曲。smoothstep 组另拒绝重叠的独立效果/滤镜。

已有证据：各线性子集有正反向/静止与非零源入点编号视频对照，并在改变幅度和时长后独立正式重建，核相对间距、字号/图形大小及源帧。smoothstep 组用缓动、线性与相同理论位置的静态组，核四分之一、四分之三实际位移，分别量面板见证块、完整文字外框、相对间距和到位停留。指定静帧曾出现时间戳合格但起点缺组；失败帧要剔除并保留，独立会话或换采样顺序后恢复，不能宣称共享预览已修复。

与其他能力的组合：组外静音曲线视频见 [曲线变速](#speed-curve-groups)，组外人物遮罩见 [人物遮罩绑定](#matting)。

未验证：UI 编辑重开、连续视听、导出。

使用：边框、文字和面板成组运动时，先在像素坐标里算共同中心，再转回各轴单位，并采样中途插值。缩放时相对间距随倍率变化，按倍率归一化判断，不要求固定像素间距。给各层相同参数不自动证明共同移动。

## 静音视频曲线变速

状态：11.5.0.14471 已准入静音视频两至三点曲线；可组合静态零羽化矩形、有限动态窗口与有限图片白字组。其余曲线变速、倒放与曲线音画同步暂存。计划字段见 [计划格式 · 曲线变速](plan-format.md#曲线变速)。

### 基本契约

- 只接受无音频流的视频且 volume=0。含声音的视频即使 volume=0 也不准入；不为准入自动剥除原声。需要原声时用现有固定变速。
- 两个或三个点；x 为有限数值、严格递增、首 0 末 1；y 限 0.5–2。duration 仍是时间轴秒数。通常省略 speed，由校验器推导；显式 speed 必须与推导值相同，否则拒绝。
- 静态 fit/transform 可沿用。拒绝：该片段的运动/透明度关键帧、motion_easing、转场（含上一片段转入）、效果/滤镜/动画/混合/色键/背景/调色、重叠独立效果滤镜、把该视频放入复合；图片/音频/文字上的 speed_curve、多于三点、自定义预设。
- 没有补帧、帧融合或外部效果烘焙。

时间映射：

- x 是选定源区间的归一化进度，不是目标时间轴进度。每对相邻点 `w=(x2-x1)/((y1+y2)/2)`；平均速度为 `1/Σw`，所需源长度为 `duration×平均速度`，目标时间锚点为累计 w/Σw。
- 例：非对称三点 `(0,.5),(.25,2),(1,1)` 平均速度为 10/7，中锚点在目标进度 2/7 处，不在 25%。
- 区间内插值来自原安装模块 15123 的三段模型，不能用简单线性速度积分替换，也不能用平均速度映射运动关键帧。

生成与校验：

- 写入独立引用的 `materials.speeds`：type=speed、mode=1、speed 为推导平均值，curve_speed 含空 id/name、source_platform=0 与原点数组；片段 speed 同步设为平均值，源/目标 Timerange 按计划微秒舍入。
- verify 检查引用数量、mode、两处标量、完整曲线、源路径与两类范围；只放行计划请求的受限动态蒙版属性组，再由 verify_masks 完整核时间/值/手柄/材料与重复组。未请求的曲线和其他源运动键拒绝。
- 普通固定变速仍为 mode=0、curve_speed=null；视频标量按生成库微秒舍入后的源/目标比值核对，不误拒短片段的舍入差异。
- 后台普通 N-API 实测参数：`video.setCurveSpeed` 为 `segId,mode:1,normalSpeed:平均值,curveSpeedPoints:[{x,y}],curveSpeedResourceId:"",curveSpeedName:""`；普通速度为 `video.setSpeed:{segId,normalSpeed:2,mode:0}`。前端 action 的 value 不能直接照搬给 N-API，accepted 可能没有改变目标参数。曲线操作会保留之前的标量 speed=2，而点和实际时长/帧号已改变，回读以真实曲线与范围为准。此接口只在独占测试会话验证，不连接用户工程。

已有证据：不同源入点/时长与非对称点的原生离散静帧映射。离散静帧只证明源/目标映射，不证明连续播放、音画同步或 UI 保存重开。生成器保留独立可编辑的 speed 与 common_mask 材料。

复验：`scripts/speed_curve_self_check.py --out 新目录 --video 静音5秒60fps测试视频`，覆盖正式生成/离线发布/交付、静态矩形组合生成与离线发布，非法点/类型/范围/原声/组合、动态/羽化/旋转/反转/圆角蒙版拒绝，输出身份/引用/标量/曲线/蒙版资源路径与尺寸/源目标时长篡改拒绝，普通速度及微秒舍入回归和源不变。普通工程保留自身 UI/音频状态，研究结果不转成新工程的全片质量保证。

## 离线单目标跟踪与位置关键帧

状态：受限离线路线，使用 OpenCV CSRT 与 PyAV 实际视频 PTS，不是剪映的原生 tracking 字段或宿主算法任务。依赖见 `scripts/requirements-tracking.txt`，不需要模型权重；跟踪与草稿应用是两个明确步骤：

```powershell
python scripts/tracking.py --input video.mp4 --bbox 20 30 40 40 --start 0 --duration 2 --out tracking-new
python scripts/tracking_apply.py plan.json --tracking tracking-new/tracking.json --source-index 0 --target-index 1 --out plan-tracked.json
```

文字目标使用同一个入口：`tracking-apply 计划.json --tracking 跟踪目录/tracking.json --source-index 0 --caption-index 0 --offset-x 0 --offset-y 20 --out 新计划.json`。caption-index是captions数组索引，与原target-index图片目标互斥。文字须显式x=0/y=0、style.auto_wrapping=false、水平单行、默认字体、无transform/已有关键帧/动画/缓动/文字曲线/glow；使用显式像素偏移表达布局，正X向右、正Y向上。偏移只用于文字，图片非零偏移拒绝。每个锚点须严格在画布内，但不保证字形完整在画内、阅读时长或长文本可读性。文字保留原文与静态样式，生成普通原生position_x/y关键帧，支持裁入点与固定速度，不将源时间或时间轴起点加进局部关键帧。

首框 x/y/宽/高为原视频整数像素；首个实际帧在请求 start 之后时，coverage_start 如实记录，不猜第一段轨迹。单次最多 1800 个选中帧；检查图、逐帧框、实际覆盖区间及完整源 SHA256 保存在输出目录。失跟或框出画时状态 lost、退出码 2，保留部分证据；apply 拒绝此结果。旋转元数据、非方形像素、缺失/倒退时间、非法框或越界范围拒绝。PTS 归一化首帧为 0 并按编辑器微秒量化，不用平均帧率推算 VFR 时间。

apply 仅接受：源视频与画布像素尺寸一致、contain、无画面变换/运动/动画/曲线变速/合成；目标可为另一个非主轨静态图片（保留静态 scale_x/scale_y/alpha），或下述默认字体静态单行文字；两类目标时间轴范围均须与源片段相同。支持源入点及线性速度，轨迹必须覆盖全部源范围，路径/大小/尺寸/SHA256 必须匹配。内部采样线性插值，末个已知帧仅在其有效显示区间内保持；不预测未知区间。生成可编辑 position_x/y 关键帧，不烘焙视频，不覆盖已有计划或运动。完整计划校验后才写新文件，再按普通 build/publish 流程交付。

证据边界：已验证合成目标的真实跟踪、失跟负例、计划/build 与独立原生关键帧回读，并核对三个原生后台静帧的标记位置。默认字体文字另经实际MCP跟踪→应用→validate/build/离线publish、原生关键帧回读及三个独立后台静帧的文字位移核对。ACP夹具的轨迹为合成数据，只证明工具传输与构建；真实CSRT验收另存工作区。真实素材仅有短区间与抽帧检查。CSRT 返回成功不证明语义身份、遮挡后重识别或长时无漂移；不据此声明车牌/人脸等隐私对象“已可靠遮挡”。跟踪框大小变化目前只用于求中心，不自动生成缩放或轮廓蒙版。UI 保存重开、完整播放与导出另验。

| 蓝绿饱和度组合 | blue_hsl/green_hsl同时填写且二者均恰好saturation=-60；材料按蓝→绿生成，青色选择范围叠加；其他配对和第三通道拒绝，沿单张静图共同限制 |

蓝色与绿色 HSL 的共同限制：独立计划恰好一张 640×360 图片，匹配 640×360/30fps 画布，contain，start=0、duration=2 秒，source_in=0、speed=1；图片无 transform/运动/动画/效果/蒙版/其他调色，计划无音频/文字/复合/独立效果滤镜。一个 blue_hsl 对象只含 hue、saturation、lightness 之一；一个 green_hsl 对象只含 hue、saturation、lightness 之一；未写分量固定 0。原生 hsl_color_type：蓝色 6、绿色 4。除上述双−60饱和度配对外，绿色与蓝色/红色 HSL、曲线或局部区域共存即拒绝。除上述静音蓝/绿色单通道饱和度视频例外外，其他数值、视频、多镜头、其他时长或尺寸、连续色相范围、绿色明度的视频或其他取值都拒绝；不从这些子集推定全 HSL 可用。证据为正式生成、逐参数/资源/引用/开关回读、离线发布与交付，以及独立原生静帧（蓝色饱和度另核红/绿/灰控制不变，绿色饱和度另核蓝/红/灰控制不变）。

绿色明度另锁11.6.0.14552与原生运行文件身份，仍复用已核HSL缓存，不改原资源。预览核实际--install及正式计划/原生材料，材料全丢也按计划声明拒绝；原生fps/画布、通道与数值类型和布尔开关须保持。−30/0/30各正式MCP构建/发布/迁移，原生控制帧和多时刻一致；不等于任意照片质量或全部HSL已准入。

<a id="transcription"></a>
## 离线转写（transcribe）

- 状态：已准入的独立脚本，不是计划字段、不联网、不需要宿主 token。`scripts/transcribe.py` 把一条可解码的媒体转成逐段文本，写 `transcript.json`（`{segments, textAll}`）、`transcript.txt`（逐段 `[起 → 止] 文本`）与 `字幕.srt`（只在有 cue 时写），另写 `transcript-report.json` 报告。
- 前置（都由调用方提供，Skill 不带）：① faster-whisper 模型目录（HF 缓存目录，或直接给含 `model.bin` 的快照目录），`--model DIR` 或环境变量 `JIANYING_WHISPER_MODEL`；本机实测 `models--Systran--faster-whisper-base`（`model.bin` 145,217,532 B / SHA256 `D01C3014…A0A6A9`）与 `-tiny`（75,538,270 B）。② 运行这个脚本的 Python 里要有 `faster-whisper`（CTranslate2 后端，**不需要 torch**）；Skill 从不自己装包。缺任一项直接拒绝，不静默降级。
- 生成：`transcribe.py --input 媒体 --out 新目录 --model 模型目录 [--language zh|auto] [--beam-size 5] [--compute-type int8] [--threads 0] [--no-vad] [--max-seconds 秒] [--word-timestamps] [--verbose]`。FFmpeg 解码成 16 kHz 单声道 PCM16 后用 stdlib 读入（绕过 PyAV：本机 `av 19.0.1` 拒绝 faster-whisper 传的 `metadata_errors` 关键字）；进入模型前设 `HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE` 与 `local_files_only=True`，模型缺失只会拒绝、不会联网下载。
- 报告：逐段起止与文本（含 `avg_logprob` / `no_speech_prob` / `compression_ratio`）、语言与概率、时长与 VAD 后时长、段数与字数、推理秒数与 RTF、模型文件清单及 `model.bin` 哈希、参数快照与五条边界；stdout 是同一份 JSON，失败时 `{"status":"failed","error":…}` 且 rc=1。
- 拒绝：没有模型 / 模型目录无效或路径不存在、输出目录已存在、`--beam-size` 不在 `[1, 10]`、`--compute-type` 不在 `int8`/`int8_float32`/`float32`（CPU 限定）、`--language` 非 `auto` 且不是 2–3 位小写代码、`--max-seconds` 超出媒体、输入不是文件、输入没有音频流（FFmpeg 报错原样透出）；拒绝时不创建输出目录。
- 性质与边界：`字幕.srt` 与 [captions](plan-format.md#captions字幕和标题) 的字段同形，逐段起止与文本可直接写进计划；但文本是模型原样输出——**不做人工改写、不补标点、不逐字对齐**，默认时间只有段级（`word_timestamps=False`）；显式模型词级子集见本页“模型词级时间与独立文字段”。本机实测 15 s 中文素材：8 段 / 59 字 / 覆盖 0.000→15.000 s / 语言 `zh` 概率 1 / RTF 约 0.07–0.10（≈10–14× 实时），重跑文本与逐段起止逐字节一致；**未与剪映官方智能字幕逐字比对**（本机没有官方转写可对照），离线结果不等于官方 ASR 完成，也不能据此声称逐词样式。静音输入 0 段，且不写 `字幕.srt`。
- 复验：`scripts/transcribe_self_check.py --out 新目录 --model 模型目录`（含原18项及词级数据/拒绝/静音检查：模型解析与哈希、SRT 时间戳格式、48 kHz 立体声重采样、静音不出 cue、报告与磁盘对账、重跑确定性、十类拒绝各留 JSON 且不留输出目录、`--max-seconds` 真裁音频）。需要 faster-whisper 与模型在位；`run_checks.py` 在缺 `--whisper-model` 或该解释器没有 faster-whisper 时记成 `skipped` 并写出原因。

### 转写结果导入剪辑计划

`scripts/captions.py 计划.json --transcript 转写目录/transcript.json --index 0 --out 新计划.json [--group clips|audio] [--track captions]` 将一个或多个所选片段对应的完整语句写入新计划；批量写 `--index 0 2 3`，序号从 0 开始。时间按 `片段.start + (语句媒体时间 - source_in) / speed` 换算，默认使用原文和段级时间；词级需显式 `--level word` 并满足本页词级子集，不是文稿强制对齐。只增加字幕，保留已有字幕；新字幕使用计划格式的默认样式，可在新计划中调整。

转写目录必须有同次 `transcript-report.json`，报告成功且语句数组一致；源路径和字节大小须匹配所选素材。这是路径/大小校验，不是素材内容哈希证明；素材更换后应重新转写。新转写报告写绝对输入路径；旧报告若仅有相对路径则拒绝猜测原工作目录。

曲线变速、带 `composites` 的计划、切断半句、同轨字幕冲突、主画面外字幕、无完整语句、来源缺失/不符和已有输出文件均拒绝。不会默默裁掉半句却保留整句文字。跨目录另存复用迁移逻辑固定素材及嵌套依赖路径；新增轨道会补入已有 `layer_order`，完整计划校验通过后才排他创建输出。后续仍执行 `editor.py build` 与原有交付流程，不自动发布。

复验入口：`scripts/captions_self_check.py --out 新目录`，不需要模型；覆盖正式 validate/build 后的文本和微秒时间回读、截取/速度映射、原计划不变和拒绝边界。已登记到 `run_checks.py`。

<a id="karaoke"></a>
## 动态逐词高亮字幕

状态：已接入完整的“已知词时间→同组全文持续显示并按词变色→原生可编辑草稿”流程。`captions --karaoke-mode active|cumulative`复用现有字幕导入与原生局部文字颜色样式；不依赖新模型或额外资源。借鉴 [Aegisub的卡拉OK时序](https://aegisub.org/docs/latest/ass_tags/#karaoke-effect)，输出的是多个连续时间状态的原生文字片段，每个片段保留完整组文本和可编辑局部样式；不是同一个文字对象的颜色关键帧，也不是文字图片或烧录字幕。

- 输入一：本机`transcribe --word-timestamps`的transcript.json与原transcript-report.json，显式`--level word`；源文件路径/字节/SHA、报告一致及合法词时间检查保持。原词与分隔符保留，ASR词时间仍是模型估计，需审阅；不会因此获得文稿强制对齐。
- 输入二：词/音节级纯文本SRT，每cue代表一个已知时间单元；必须显式`--timebase source|timeline`。默认单位间插入空格，中文可用`--karaoke-joiner=`。不把只有整句时间的SRT按字数拆时；外部SRT与媒体是否对应由调用方负责。
- 每个所选片段先按source_in、固定speed和timeline start映射完整时间单元，再独立编组；支持多片段、重排和重复素材。部分切词、源SHA变化、重叠/零长/缺时间、曲线变速与复合等既有拒绝边界保持。
- active仅当前单元变色，内部停顿恢复全文基色；cumulative累计至当前单元末，停顿保持累计色。显示组从第一个词起到最后一个词止，首尾不凭空延长。按原ASR分段、字数/单元数或大间隔分组，默认12字符/6单元/1秒间隔；单词超上限拒绝，不能猜内部时间。
- 可设`--karaoke-color #RRGGBB`、`--karaoke-size`、`--karaoke-max-chars`、`--karaoke-max-words`、`--karaoke-max-gap`。原生仍沿用默认字体、中文/ASCII/已准入标点与单行局部样式边界；长句应分显示组。每状态文本可编辑；统一改全文时从词时间源重新生成，避免只改一个状态。平滑逐字擦色、额外字形/字体及未知时间不在此入口中冒充已实现。
- 输出新计划，不改源计划、媒体或时间文件；生成后走validate/build/verify、离线发布和迁移。词数和字幕状态数不同，内部停顿也有状态。源时钟用整数微秒，避免浮点拼接制造接触边界重叠。

示例：`python -m jianying_engine captions plan.json --transcript transcript.json --level word --index 0 --karaoke-mode active --karaoke-size 14 --out karaoke-plan.json`；随后validate/build。人工词SRT改用`--srt words.srt --timebase source --karaoke-mode cumulative --karaoke-joiner=`。工作台中的Agent使用同一captions操作。复验`checks --only karaoke karaoke_flow captions text_highlight coverage`。结构、原生抽帧和工作台接口测试不等于真实模型创作、实机保存重开、完整视听或导出。

<a id="separation"></a>
## 离线人声分离（separate）

- 状态：已准入的独立脚本，不是计划字段、不联网、不需要宿主 token。`scripts/separate.py` 把一条可解码的媒体拆成 `vocals.wav` 与 `accompaniment.wav`（`--stems all` 再加四路原始 stem），并写 `separation.json` 报告。
- 前置（都由调用方提供，Skill 不带）：① htdemucs ONNX 权重，`--model PATH` 或环境变量 `JIANYING_DEMUCS_MODEL`；本机实测文件 `htdemucs_fp16weights.onnx` 165,612,636 B / SHA256 `D05C269D…5DB70A`（hf-mirror 的 StemSplitio/htdemucs-onnx）。② 运行这个脚本的 Python 里要有 `onnxruntime`（CPU）；**不需要 torch**，Skill 从不自己装包。缺任一项直接拒绝，不静默降级。
- 生成：`separate.py --input 素材 --out 新目录 --model 权重.onnx [--stems pair|all] [--overlap 0.25] [--verbose]`。全程用 FFmpeg 解码到 44.1 kHz 立体声（48 kHz 或单声道输入会被重采样）；分段长度**取自模型自己的输入形状**（本机 343,980 样本 ≈ 7.8 s），相邻分段按 `--overlap` 用三角窗叠加；最后一包的补零尾巴按权重阈值置零，不做外推。
- 报告：`separation.json` 记模型路径/字节数/SHA256、分段与重叠、包数、推理秒数、四路 stem 的 RMS、重建相对误差与生成文件字节数；静音输入的相对误差没有定义，记为 `null`，不能用 `NaN` 冒充标准 JSON 数值。stdout 是同一份 JSON，失败时 `{"status":"failed","error":…}` 且 rc=1。
- 拒绝：没有模型或模型不是文件、输出目录已存在、`--overlap` 不在 `[0, 0.5)`、输入不是文件、输入没有音频流（FFmpeg 的报错原样透出）；拒绝时不创建输出目录。`onnxruntime` 缺失、模型初始化失败（例如内存不足的 `bad allocation`）走同一条 JSON 拒绝路径。
- 性质与边界：拆分质量由权重与素材决定，脚本只保证分段、叠加与报告。本机实测夹具是**合成混音**（中文语音 + 合成乐器床 10 s：重建相对误差 0.0495、`vocals`↔原人声 r=0.9977、反向串音 ≈0、CPU 约 1× 实时）；2026-10-17 补**真实歌曲**一次（mp3 192 kbps / 44.1 kHz 立体声 / 267.964 s：`inference_seconds 180.37` = **0.67× 实时**、重建相对误差 0.017725、stem RMS drums 0.08247 / bass 0.00302 / other 0.13741 / vocals 0.16，证据 `运行数据\真实歌曲分离-20261017\`），鼓与贝斯只此一次读数、`bass` 明显偏小，不据此下结论；stem 顺序沿用 demucs 约定且只用能量交叉核对。`--out` 里的 stem 当普通音频素材写进计划，界面播放与导出归用户。
- 复验：`scripts/separate_self_check.py --out 新目录 --model 权重.onnx`（覆盖模型形状、48 kHz 重采样、单包叠加与重建误差、静音与严格 JSON 报告、pair/all 两种产物与报告对账、环境变量发现、六类拒绝且不留输出目录）。需要 onnxruntime 与权重在位；`run_checks.py` 在缺 `--demucs-model` 或该解释器没有 onnxruntime 时记成 `skipped` 并写出原因。

<a id="ducking"></a>
## 离线自动闪避（ducking）

- 状态：已准入的独立脚本，不是计划字段、也不在 build 内部触发。`scripts/ducking.py` 从分离后的人声 stem 或显式语音区间算出包络，写进目标轨（默认 `music`）片段的音量 `keyframes`。
- 输入：PCM 16/24/32 位 WAV（其它位宽直接拒绝），或 `--speech-json` 给的 `[{start,end}]` / `{"segments":[…]}`（媒体时间）；两者不能同时给。判据：20 百分位当噪底，阈值取 `max(噪底 + 10 dB, −55 dBFS)`；短于 0.15 s 的爆音丢弃，间隔小于 0.25 s 的段合并。阈值跟着噪底走，所以歌曲这类底噪高的素材会得到比 −55 dBFS 高得多的阈值（实测一首真实歌曲：噪底 −35.308 dB ⇒ 阈值 −25.308 dB），这是"这首歌自己的安静段落"口径，不是通用语音检测。
- 生成：`ducking.py 计划 --vocals 人声.wav --out 计划副本.json [--track music] [--duck-db -12] [--attack 0.15] [--release 0.35]`。形状：语音前 0.15 s 从 base 下压、语音内保持 `base × 10^(duck_db / 20)`、结束后 0.35 s 抬回 base；区间是 stem 的媒体时间，按 `(media − source_in) / speed` 换成片段局部时间。全段语音仍保留降音键；零 attack/release 用相邻微秒键表达切换。只写新的计划副本，不 build、不读用户草稿；跨目录另存时复用迁移逻辑固定素材及嵌套依赖的绝对路径，缺依赖则拒绝，不改变原计划。
- 拒绝：`--duck-db` 大于等于 0、非有限数值、同时给两种输入、输出文件已存在（包含计划、语音区间文件或音频素材）、目标轨没有片段、区间结束不大于开始；输入区间先排序再合并。前置校验失败不创建输出文件。
- 性质与边界：包络是确定性的音频分析结果，可复算、可与区间对拍；它不改变剪映的原生混音算法，也不代表分离质量或最终听感。**用户侧听感证据（2026-10-17，仅一次、一首歌）**：真实歌曲（4 分 28 秒、46 段）生成的草稿由用户在剪映内试听，用户报告效果很好（User said (m04088)「我已试听 效果很好」）；这条只证明该稿可听、该次闪避听感可接受，不构成其他素材、阈值或分离质量的保证。分离见 [离线人声分离](#separation)：脚本在 Skill 内，但权重与运行时由调用方提供（模型不随 Skill 分发）；没有它们时用显式区间，或让用户在剪映里手工分离，不假装自动分离。
- 复验：`scripts/ducking_self_check.py --out 新目录`（不需要原生用户数据），覆盖两段检测、包络 7 点形状、stem 与区间两条路径等价、静音不产生键、整段语音与零 attack/release（含变速）、跨目录路径保持、既有输入保护与非有限数拒绝、正式 build 的逐点回读、键时间/增益篡改拒绝、四类非法计划与五类 CLI 拒绝、拒绝不留半成品。

离线输出的失败边界：转写、分离及闪避的前置参数拒绝不创建新产物；写盘中途失败可能保留已写文件。目录或单个输出存在不等于成功，须核对退出码及完整成功报告；保留失败证据并换新输出路径重试，不自动清除已有目录。

<a id="offline-denoise"></a>
## 离线 FFT 降噪音频

- 独立操作 `denoise-audio --input 本地媒体 --start 0 --duration 10 --noise-floor -50 --reduction 6 --out 新目录`，不是build隐式步骤或原生audio[].denoise字段。不需宿主token、模型或新依赖；复用FFmpeg afftdn白噪声型估计，明确噪底−80至−20dB及降噪量3至24dB。两参数必须显式给出，不把数值当音质评分，也不从语音/音乐自动推断干净参考。
- 输入须恰好一个音轨、音频起点为0、44.1/48kHz单/双声道；不自动重采样/downmix。start≥0、duration为0.1–300秒，按原采样率就近量化样本区间，报告请求值与实际区间。选区须在音轨时长内，实际解码样本不足直接失败，不以补静音补足素材。FFprobe和FFmpeg均限制file/pipe协议，不接受联网地址或播放列表网络跳转。
- 输出dry.wav及denoised.wav均为原采样率/声道PCM16，前者为原选区的解码对照，后者是新音频素材；不覆盖原片或已有输出。固定white、tn=0、tr=0、nl=none及报告中的其余滤镜参数；各声道按同一显式噪底处理，不生成语义人声/背景分离。输出报告保留源/结果SHA256、实际样本数、采样峰值及满幅样本数、滤镜参数和FFmpeg版本。
- afftdn样本数不变仍可能存在内容延迟。每次先以同采样率/声道/滤镜执行独立脉冲，要求每声道有唯一保留峰、相同且有限的延迟；失败拒绝。按量测延迟补零排出滤镜尾部，再裁回原选区样本数并归零PTS；零尾仅供滤镜排空，不替代原素材覆盖。结果回读实际PCM字节和样本数，不以容器duration或退出码证明音画对齐。
- 将output_media作为普通audio[].path，source_in=0；如替代视频原声，视频用报告source_in并明确volume=0，避免双声。保留输出目录，不再叠加原生denoise字段。降噪已经烘焙为独立素材，时间/音量仍可编辑，频谱处理参数不能在剪映里撤销；原片和dry.wav作为对照保留。
- 证据：已知干净双音调与固定白噪声夹具的噪声段能量/参考误差、声道、早中尾瞬态及多采样率裁剪通过；实际中文AAC非零入点经真实MCP降噪→validate/build→offline publish，dry与独立全解码切片逐样本相同，处理前后波形互相关lag=0。ACP确定性Peer另走真实MCP到草稿；不等于真实模型Agent操作。声音产物是实际PCM；原生静帧不用于证明声音质量，未进行原生播放器PCM捕获、人工听辨、UI保存重开、完整播放或导出。
- 边界：适用于白噪声型底噪估计，不承诺任意真实语音更清晰、音乐无损、非平稳噪声消除、响度/真峰值目标或全片音画同步。FFT处理可能损伤语音/音乐，应比较dry和denoised；这是独立开源离线路线，不表示剪映宿主离线降噪任务或原生PCM导出已打通。
- 复验：`checks --only offline_denoise coverage`，不需要原生用户数据、模型或音频设备。既有`denoise`检查继续验证原生实时参数，不能用其中一条替代另一条。来源及外置证据见工作区`Skill维护层/变更/2026-10-19-离线降噪入口-v1`。

## 独立音频受限响度参数

- 状态：已准入。计划字段 `audio[].loudness` 见 [计划格式 · audio](plan-format.md#audio音频)；省略字段不启用。
- 条件：目标仅 −23 LUFS；44.1kHz 双声道、speed=1、volume=1、至少 3 秒的独立音频。同片段不能有淡入淡出、音量关键帧或降噪，不能放进复合。其他目标、格式与组合直接拒绝。
- 测量：FFmpeg 只测选定源范围的 EBU R128、采样峰值与真峰值，测完丢弃音频输出；剪映原生材料执行增益，不生成归一化音频文件。静音、近静音或预测真峰值超过 −1.1 dBFS 时拒绝；没有限幅器。该阈值按测量精度留余量，不保证有损编码后的真峰值或全片混音响度。
- 生成：`materials.loudnesses` 保留启用、目标、源范围与测量值，并使用安装 schema 默认的空 `file_id`，不猜字节 MD5。剪映保存重开会自行补全身份，原生补全规则仍未知。生成稿按当前源路径、范围和重新测量的参数验证；同名替换素材或旧缓存不能用于新的声音验收。
- 已有证据：新输入首次 WAV 输出的目标检查、保存重开、原生身份补全与正式回归；覆盖两段 8 秒合成输入。WAV 与有损编码分开验证：MP3 的绝对响度可能超出目标误差，不为此写入经验补偿增益。文件尾部填充与相对延迟分开核对，不写固定补偿增益。
- 不包含：后台 PCM 导出、原生算法任务 ID/进度/取消、实际试听、任意节目/区间/混音精度。真实项目保留自身试听状态，成片导出仍由用户完成。
- 复验：`scripts/loudness_self_check.py --out 新目录 --plan 带loudness的测试计划`，覆盖正式 build/离线发布、参数与引用篡改、非法组合、格式、静音与真峰值余量拒绝及输入不变。

## 外部或人工校正 SRT 导入

同一 `captions` 操作也支持 `计划.json --srt 字幕.srt --timebase source|timeline --index 0 --out 新计划.json [--group clips|audio] [--track captions]`。`--srt` 与 `--transcript` 互斥，SRT 必须显式给时间基准：`source` 表示所选原媒体时间，复用上述截取和线性速度映射；`timeline` 表示最终计划时间，保持字幕时间不变。两者都只导入完整落在所选片段区间内的字幕，完全在区间外的条目略过，跨边界半句拒绝；多段剪辑可用同一次 `--index 0 2 3` 显式选择，完整映射后生成一份新计划；范围见本页“多片段字幕映射”。

准入子集为 UTF-8（可带 BOM）、LF/CRLF、正数递增编号、`HH:MM:SS,mmm --> HH:MM:SS,mmm` 时间及纯文本多行内容。保留文字、空格和换行，不解释 HTML/ASS 样式或位置标记，遇到它们拒绝；其它编码须先明确转换。不猜时间基准、不修复损坏字幕、不裁半句、不覆盖已有计划。曲线变速和 composites 仍拒绝。输出报告标记 `input_format=srt`、`timebase` 和调用方提供的来源；SRT 与素材的对应关系未自动核实，不冒充 ASR 原样结果，原转写模式的来源报告检查保持有效。

该路径已通过字幕专项、工作台确定性 ACP 测试 Peer → 真实 stdio MCP → captions/validate/build 的中文多行文本和微秒时间回读。测试 Peer 没有调用模型；证据只到可编辑草稿结构，剪映 UI、保存重开、视听与导出分别验收。

## 离线短片段倒放

统一CLI/MCP操作 `reverse --input 原片 --start 0.5 --duration 1 --audio reverse|mute --out 新目录`。复用本机FFmpeg，生成新 `reversed.mov`（H.264/yuv420p，reverse声音为PCM16）与 `reverse-report.json`，原素材不变。它是时间逆序、重新编码后的源素材，不是剪映原生reverse开关；原帧/声音不能在草稿中逐点恢复成正序，须保留原片和来源报告重新生成。裁切、重排、图层与后续效果仍通过普通计划生成可编辑草稿。

准入为一条真实视频流、零起始时钟、CFR整数24/25/30/50/60fps、偶数尺寸、最多1920×1080像素、8-bit YUV420、方像素、无旋转/隔行/HDR。必须显式选择音频策略：reverse需要一条零起点且覆盖所选区间的44.1/48kHz单/双声道；mute输出无音轨。选区按帧对齐且至少两帧，最长10秒，`宽×高×3×帧数`解码帧缓存估算不超过512MiB；这不是进程RSS上限，长片应先明确分段。超限、不规则帧时钟、来源越界、音频缺失/错位及已有输出拒绝，不自动缩放/剥音/补帧。输入协议限制为本地file/pipe，不能通过本地播放列表发起联网。

把报告的 `output_media` 用作普通 `clips[].path`，`source_in=0`，duration按报告，是否保留声音须显式写volume（默认0）。原片与新逆序素材目录都保留，不自动镜像旧计划中的字幕、关键帧、变速、转场或效果范围；本次不新增计划reverse字段。失败应核退出码/报告，最终I/O失败可能留部分目录，不可按文件存在认定完成。

真实输入处理会回读帧数/时间、时长、尺寸、声音策略与源/产物哈希；专项独立解码逐帧识别顺序、逐采样验证PCM逆序，并经过普通validate/build/离线publish。工作台确定性ACP测试Peer经真实MCP执行reverse→captions→validate→build；Peer不是模型。新工程的UI打开、保存重开、连续视听及导出仍分别验收。剪映宿主原生倒放、复杂计划镜像、VFR/非整数fps、旋转/HDR及长片段仍未准入。

复验：`scripts/reverse_self_check.py --out 新目录`，已登记 `checks --only reverse coverage`。参考[FFmpeg reverse/areverse](https://ffmpeg.org/ffmpeg-filters.html#reverse)的缓存与截取边界；不新增或分发FFmpeg二进制。


## 多片段字幕映射

已有 `captions` 操作的 `--index` 支持一个或多个序号：`captions 计划.json --transcript 转写目录/transcript.json --index 0 2 3 --out 新计划.json`；SRT使用原有 `--srt 字幕.srt --timebase source|timeline`，可选 `--group audio`。索引是指定group数组中的位置，不是轨道号或时间排序，单索引旧用法继续支持。不自动扫描/猜测要处理的片段，也不覆盖原计划。

转写JSON或source时间SRT的一次批量必须指向同一个媒体路径；转写仍验证同次成功报告、绝对路径、源大小及段数组一致性。允许源区间重排、重复使用和每段不同固定速度；重复使用的完整原句会在对应目标位置再次出现。timeline时间SRT可对应不同来源，直接保留最终时间。选段在目标时间轴上必须互不重叠，允许相邻或有空隙；重复索引、范围外索引拒绝。每段单独执行原整数微秒映射，再按目标时间排序新增字幕。

没有完整语句的选段可有0条字幕，报告mappings逐段列数；若全部选段都无完整语句，则拒绝。任何片段切断语句、曲线变速、全计划composites、已有同轨冲突、超出主画面或来源检查失败，整批不写输出。即使后续选段失败也不留下前半份计划。只在全部映射及完整编辑计划校验通过后排他创建新文件；硬件/写盘失败仍需检查退出码，不能按文件存在判断成功。

多索引本身只做批量固定速度映射，词级须另按本页模型词级子集选择，不自动切半句或把跨镜头语句合成新文本，不支持一份源时间字幕猜配多个不同媒体。复杂混源转写可按来源分别生成新版本，最终时间SRT则须显式声明timeline。报告保留selected_index单选兼容，并增加selected_indices和mappings；已有字幕/样式、原文、多行、层序与素材引用不变。

已覆盖同源重排/重复/速度/静音选段、独立音频组、timeline混源、拒绝边界、正式validate/build/离线publish的微秒文本回读，以及确定性ACP Peer经真实stdio MCP调用多索引captions→validate→build。不是模型任务或UI保存/完整视听/导出证明。复验仍为 `checks --only captions coverage`。


## 模型词级时间与独立文字段

显式 `transcribe --input 媒体 --model 本地模型 --word-timestamps --out 新目录` 启用已安装faster-whisper的模型词级估计。默认不带此开关仍是原段级行为。transcript.json和同次报告的segments增加原words数组（word/start/end/probability），段级字幕.srt保留，非空词结果另写词级字幕.srt；报告params.word_timestamps=true/level=word、stats.word_count和audio.sha256。没有新权重/依赖下载，不联网、不需要宿主token，FFmpeg输入也限制本地file/pipe协议。

`captions 计划.json --transcript 转写目录/transcript.json --level word --index 0 2 --out 新计划.json` 将每个模型词单元生成独立原生可编辑文字段，继续复用固定速度、多索引与来源规则。词级需同次成功报告、段数组一致、显式word模式和源SHA256匹配；默认segment模式保留旧路径/大小检查。不能给SRT加level=word冒充模型证据；普通SRT仍按调用方声明的cue导入。

每个词须原文非空/无NUL、有限时间与概率、正时长、段内且不超过源音频范围，全部词单元按序不重叠；拼接必须逐字节等于该段原文。缺词、零时长、重叠、越界或拼接不符时整体拒绝，不补零时长、不重排、不按字数平摊。静音可为0段/0词，不写词级SRT；无完整词不能导入空字幕计划。按词边界可以截断父句，但截断任一模型词仍拒绝；原segment模式仍拒绝切半句。

这是模型提供的时间估计，概率不是人工校准准确率，中文词单元可能有多个汉字。不是用户文稿强制对齐、逐字时间、官方智能字幕、说话人分离或同一句内的重点词/卡拉OK样式。生成的是独立文字片段；短词阅读时间、字形/排版、连续听感与真实语音对齐准确度须在当前任务核验，不能从结构回读推得。曲线变速和带composites计划仍拒绝。

本机base模型真实中文短音频已复跑文本/词时间一致，48个词单元经真实MCP转写→词级导入→validate/build/离线publish逐项微秒和文本回读。便携ACP夹具只用合成词数据核工具传输/导入；真实ASR证据另存工作区，不混称模型长任务。复验为 `checks --only transcribe captions coverage --whisper-model 本地模型目录`；未提供模型应跳过并如实报告，不算通过。UI保存重开、完整视听、导出和人工听辨对齐未验证。

<a id="text-global-alpha"></a>
## 原生文字整体透明度关键帧（受限接入）

`captions[].keyframes=[{"property":"alpha","time":0,"value":0},{"property":"alpha","time":1.5,"value":1}]`进入正式validate/build/回读、CLI/MCP、离线publish与迁移重建。仅文字把底层KFTypeAlpha改为KFTypeGlobalAlpha，视频仍用原类型；文字材料global_alpha与clip.alpha均保持1，透明度来自真实原生关键帧。文字与描边同步变化，保留可编辑文字和关键帧，不烘焙或复制旧稿。

- 子集：静态单行BMP白色默认字体、bold=false、style仅auto_wrapping=false；可保留默认描边或显式border=false。两点纯alpha时值0–1，可淡入、淡出或恒定值；另准入四点0→1→1→0，分别淡入、保持、淡出，其他四点值序列不开放。两种模式均首点time=0、按微秒严格递增、末点严格早于字幕结束，末点后保持；输入乱序沿既有规则排序。key time为字幕局部秒，非零字幕start不加到原生time_offset。
- 拒绝：其他字体/颜色、粗体、换行/非BMP/代理字符、静态style.alpha组合、变换/其他轴关键帧/缓动/动画/发光/弯曲/复合；重点词颜色仅按 [多色淡入淡出组合](#text-color-fade)。当前11.6.0.14552与运行文件/关键映射JS/默认字体指纹固定；预览校验实际--install，不能先验默认11.6再实际运行另一版本。
- 回读/预览核唯一GlobalAlpha组、类型/局部时钟/值、静态alpha、线性曲线/有限数值控制柄/无graph、未请求及错视频绑定；不接受旧视频Alpha或只改字面不改描边的TextAlpha替代。即使组被删掉，也按正式计划拒绝失效预览。
- 原生证据：先对照旧Alpha/GlobalAlpha/TextAlpha。旧Alpha不改变文字；GlobalAlpha使字面与描边变化，TextAlpha的描边不变。正式MCP淡入/淡出/恒定半透明及无描边组，字幕前/中/后、末点保持、非零start与发布迁移分别核验；四点包络另核淡入/淡出中间、平台边界/内部、末点后为零，白字/多色及有无描边与同值静态原生控制比较。
- 原生文本边缘使用字体渲染器自身的global_alpha语义，不能假定等于先渲染整块RGBA再线性乘alpha。实际关键帧采样与同值静态原生style.alpha控制稿比较；源码/REA静态推断与此呈现证据分别记录。
- 跨机重建需匹配安装；UI编辑/保存重开、连续视听和导出未验。复验`checks --only text_alpha`，原生帧另验。

## 多色字幕与整体透明度组合（受限接入）

同一captions条目可同时保留`highlights`和两点或受限四点`property=alpha`关键帧，形成整句含重点词/描边的原生淡入淡出；或无关键帧时使用静态`style.alpha`。文字、范围与颜色不随时间改写，仍是一个原生text和一组GlobalAlpha，不是卡拉OK、逐词高亮动画或预渲染图片。

- 复用两项既有范围：默认字体、静态单行布局、中文基本汉字/ASCII/已分配CJK全角标点，基色白/bold=false；highlights的start/end/color校验不放宽。布局style.auto_wrapping=false，可有默认描边或border=false。
- 动态：两点纯alpha，或四点值严格为0→1→1→0的淡入—保持—淡出；首time=0，所有键按微秒严格递增，末点严格早于字幕duration；只允许这组透明度键。静态：无关键帧，style可额外有alpha 0–1；静态style.alpha与动态alpha不能同时设置。

- 正式validate/build/回读、CLI/MCP、offline publish与计划迁移重建保留完整styles、颜色区间和字幕局部key clock。原生动态采样与多色同值静态style.alpha控制稿比较，不从两个单项通过推断组合通过。UI编辑/保存重开、连续视听/导出仍未验。
- 复验`checks --only text_color_fade text_highlight text_alpha`。该组合不解决其它已审计的公共门禁/恢复问题，相关加固在独立会话副本进行。

## 离线节拍候选与按拍切镜（受限接入）

`beats --input 本地音频 --start 20 --duration 16 --out 新目录`使用librosa0.11.0动态规划节拍跟踪，FFmpeg提取明确选区为22050Hz单声道PCM。需可选`[rhythm]`依赖（numba0.68.0），不下载模型或运行时联网；选区2–180秒，start为整数微秒精度。输出beats.json的相对样本索引/源选区时钟、全局BPM候选及beat-report.json的源/产物SHA256、算法实现身份和依赖版本。静音可返回0拍/0BPM。

这些是算法候选，不是校准置信度、强拍/小节线或可靠变拍追踪；可能半速/倍速。没有手工补拍或统一平移，正常速度试听和具体歌曲准确度仍须核验。参考 [librosa官方算法说明](https://librosa.org/doc/0.11.0/generated/librosa.beat.beat_track.html)，不是剪映宿主自动计算或原生节拍标记写入。

`beat-apply --plan 原计划.json --beats 检测目录 --every 4 --out 新计划.json`显式采用每第N个候选，N为1–16。按原主轨镜头顺序选择前len(clips)个边界，从0开始重新安排各镜头起点/时长，音乐截短到最后边界。候选不足拒绝，不补拍、不循环镜头；不保留原总片长。保留各素材source_in和源文件，不自动挑镜头或改内容顺序。

输入只允许至少2个连续、静音、speed1的普通主轨片段和一个start0/speed1的music片段；无字幕/其他轨/复合/效果/关键帧/转场/变速/混合/蒙版/调色，音乐无淡入出/音量键/降噪/响度。音乐路径须匹配报告源且当前SHA相同；时间由选区样本时钟减music.source_in得到，不使用慢速试听时间。按精确分数直接量化到最近帧，再转微秒；帧碰撞、超源/超音乐范围或无合法完整映射整体拒绝。

应用只写新计划，全部新计划校验通过才排他创建输出；原计划/素材不变，既有输出不可覆盖。检测产物在写出前校验，复制或复核失败回滚本次拥有的文件；它们是本机结果回执而非密码学签名。迁移后要重新检测当前音乐源，不能把旧路径报告冒充新来源；已生成计划则按普通媒体迁移和重建。

正式CLI/新stdio MCP共用白名单，工作台/Agent复用同一入口。已加载旧MCP若返回Unknown operation，连接尚未重载；可用正式CLI立即执行，不能声称旧连接已刷新或中断共享任务来掩盖状态。复验`checks --only beats beat_apply coverage`；缺可选分析依赖应明确跳过，不算通过。

原生可编辑音乐拍点标记、自动强拍/乐句判断、复杂多轨联动重排、曲线变速映射及具体作品听感仍未接入/验收。输出候选与新计划不代表已经连续播放、保存重开或最终导出。
