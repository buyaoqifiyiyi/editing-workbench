# 逐项研究与接入逻辑

用户于2026-10-08要求按能力收益逐项接入，每项独立总结为后续可遵循的方法。该授权适用于研究和维护；普通剪辑仍只调用正式准入字段。不要把“总结已写入”当作“算法已接入”。

## 每项如何结束

先定位原安装契约及实际输入/资源身份，用新输入或新的独立范围进行后台生成，再独立回读。需要证明新算法时还要核对新产物与范围；参数配置、真实渲染、声音输出、编辑保存重开分别记录。通过哪一子集只开放哪一子集，补该子集的非法输入/身份篡改/源不变与实际输出对照，沿validate/build/verify/publish/交付链维护。拒绝或质量失败时保留最小证据和下一条可检验假设，不先加生产schema。

每项报告开头仅列三项：接没接入、还有什么问题、需要什么支持。接入说明明确后台与界面、正式子集与研究状态；无需支持时直接说明。目的、输入、版本契约、调用方法、证据和失败边界折叠或链接，保留完整记录，不要求用户阅读长篇才能知道结果。测试媒体清理前留哈希/指标/回执，保留被草稿引用的输入。研究报告落在独立工作区；Skill只存影响以后判断的规则和可复用方法。

## 01 后台任务入口：调用层已验证，算法执行仍暂存

剪映11.5的 `Resources/canvas_agent/runtime/videoeditor-service.mjs` 提供域system/player/draft/edit/job，导出startVideoEditorService、stopVideoEditorService、resolveVideoEditorRuntimeConfig及requestVideoEditorServiceSelfTermination。job.submit的params.command是{domain,operation,targetId,params}；getState/getResult/cancel传params.jobId。system、job和player.subscribeFrames禁止嵌套提交。会话targetId按原安装服务映射为原生sessionId。

研究复验必须启动自己的服务、随机命名管道及会话，不连接用户编辑器。自己的Node工作进程PATH加入安装根与vm_sdk；VIDEOEDITOR_ADDON_PATH指向当前实测模块，modelsDir与algorithmConfigPath由原服务环境参数解析。退出先destroy，再stopVideoEditorService，最后调用随安装受控自终止机制；它不是算法取消。运行时身份须由当前安装核对，升级后重核契约，不照搬结果。

**成功判断分三层**：协议ok；JS队列state；原生result.accepted/error。job的succeeded只表示invoke返回，没有检查accepted。真实prepareMatting诊断可能返回accepted=false/error=unsupported_method，而job仍succeeded；必须保留并报告该原生错误。算法完成另需引擎状态与新产物，不能把load/getState成功推成算法入口成功。

原队列仅在调用前后检查AbortSignal，没有引擎停止调用或进度百分比。取消queued任务可阻止分发；running取消改写记录并丢弃结果，底层操作可能继续。原源码队列类的受控任务只验证这一层行为，未验证真实长算法取消。报告观察到的状态及耗时，不编造百分比；真实取消需另证明引擎停止、产物停止增长与资源释放。

调用层契约不新增算法生产字段；原始实验与指标留在外部研究目录。

## 02 智能/手工抠像：已有产物绑定已验证，新计算仍暂存

随安装前端video.setMatting使用segId/path，内部设置webAiMattingFlag|enableFlag；aiMattingPath不属于该契约。VideoAiMattingToggleParam的segIds/flag/removeFlag/path等是前端构造参数，不能直接当公开N-API操作。实测edit/videoAiMattingToggle返回unsupported_behavior_operation，draft/prepareMatting在修正真实path后仍返回unsupported_draft_operation；普通透明度正向/恢复画面对照成立，不把拒绝归因于全部编辑通道失效。同条件无新入口不猜域重复试跑。

分开“已有产物绑定”与“新mask计算”。已有产物绑定 clips.matting_cache 已贯通正式链路，当前子集、组合与验证方法见 [人物遮罩绑定](capabilities.md#matting)；新增组合仍按其中的单层控制、不同到位时间与仅人物/仅背景对照逐项验证。载入日志matting tasks prepared及count只表示准备；新空缓存的2秒片段正常原生播放、持续读帧并等待30秒仍无新mask，限定该条件不足以启动计算。已有绑定正式接入不表示新计算接入，抠像整项目标仍未完成。未取得正常计算提交/回调入口时记录阻塞与下一有效条件，不重复同条件猜operation；是否继续其他研究按用户当前优先级与授权决定。

原安装CLI的算法命令、XML抠像节点和宿主能力路由分别核对。host-capabilities的manifest/invoke要求正常runtime binding；宿主签发的子进程transport、caller/run与允许目录不能靠本地配置冒充。CLI静态字符串、模型文件及驱动错误提示只提供定位线索，不证明算法可调用或本机已触发某错误。网页WASM、移动SDK和云端抠图也不自动兼容Windows原生遮罩；取得实际契约与正常授权前不下载包、加载猜测ABI或外部烘焙代替。

已有缓存准入使用[admit-matting工具](capabilities.md#matting)，核实际审阅记录、源和缓存身份后再注册；UI新产物必须先过质量审阅。真实新mask及完整帧覆盖不能代替主体质量；不合格缓存即使计算成功也拒绝绑定。

复核输入/安装身份、草稿相对路径、custom ID及源范围。已测缓存的mask文件名是源时间微秒，8位单通道长度须匹配maskinfo.boundingBox.width×height；left/top/right/bottom全0不单独证明空遮罩。mocf和matting_result的数量/范围仅作覆盖证据。复用旧cache不登记成新计算；新mask另需合法提交/回调、真实新产物和帧覆盖，手工补边另需原生笔刷/种子编辑状态。

复杂背景人物的质量顺序、黑灰白底检查及相邻alpha候选复核见[合成执行顺序](green-screen.md#原生执行顺序)。游戏与真人分开评估；早期游戏样本有头发/脸部大块漏选，后续独立UI修补已恢复主要主体并保存重开；黑灰白底与局部穿插保留少量边缘残色。允许在已验证范围内复用，不能承诺所有帧/素材合格，也不推广为所有输入失败。原生静帧不证明运动模糊、时域稳定、遮挡恢复、UI编辑重开或导出。

已授权界面参与时，[人物抠像界面计算与后台复用](native-ui-advanced.md#人物抠像界面计算与后台复用)可按条件使用；原生新计算、修补、保存重开、外部审阅准入和后台新建独立稿的整条流程已通过，保留少量边缘残色。纯后台新计算仍未接入，普通任务不自动启动界面。

用户明确授权界面研究时，可在独立新稿验证新计算与可编辑补选。分别核对启用状态、提交笔刷种子、应用后计算完成、实际合成及保存重开；cyan 编辑叠色或开关勾选不证明效果已应用。失败时记录实际操作序列，不把单次开关切换推成通用根因。新种子可能连带改变其他时刻，每次补选或擦除后复查受影响范围；对照原画面区分真实缝隙／饰物与漏选／背景。缩短片段或独立选区只作新的实验条件，未取得实际对照前不承诺减少传播。智能补选仍遗漏确定的前景小块时，可用原生普通笔刷精补；运动使孔洞位置变化时核对实际前景范围，并复查黑灰白底。羽化只用于评估柔边，不能隐藏漏选或残底；缓存尺寸仅是中间产物事实，不能直接当成最终渲染分辨率。原生 UI 新计算成功仍不等于后台计算契约打通。

2026-10-16 离线路线实测结论（反方向证据，结论为「不可行」）：抠像模型与 ASR 不同——**没有裸 ONNX**。安装与用户数据全域 162 个候选里，抠像/跟踪具名模型 37 个**全部是私有容器**（`.model` / `.bytenn` / `.dat`），用剪映自带 onnxruntime 建会话时 18 个候选 **17 个失败**（原文 `Load model from <路径> failed:Protobuf parsing failed.`），唯一能建会话的是安装目录里另一个用途的 ONNX（`version-RFB-640` 人脸检测，非抠像）。算法图（`Resources\matting_config\*`）的节点类型是宿主 VE 原生图节点，由 `videoeditor.dll` / `cccreator.dll` 侧引擎执行，不走 onnxruntime。因此离线侧**只能写标签声明**（`ai` / `none` 与羽化、扩散参数），**算不出掩码**：`sam3` 需要的 `mask_ref` 在本机无从产生（`Cache\matting` 为空、现有草稿 `materials.common_mask` 全空），`ai_with_stroke` 需要的真实 `stroke_ref` 同样没有绑定资源；`custom` 的笔划几何理论上可由程序生成、不依赖模型，但**本轮只确认语义，未实测生成草稿**。证据与未验证项见 `Skill维护层\来源\抠像跟踪离线可行性-20261016\`（含「离线推理链路本身可用」的对照实验：人脸 0.99996，但那不是抠像掩码）。

2026-10-16 替代路线实测结论（不做原生抠像，改把抠像结果当素材）：**离线算好带 alpha 的 PNG，当普通图片素材叠到上层轨**。剪映对带 alpha 的 PNG **无条件认可、逐像素精确**：320×180 夹具里不透明段透出下层（红底主导色 `(255,0,0)`、19,260/19,260 像素命中）、`alpha=128` 段按 50% 混合成 `(127,128,32)`、`alpha=0` 段完全透出，渐变底对照 `max_abs_channel_diff=0`，「按黑底/白底填充」假说命中率 0.0（反证）。**无需任何掩码字段或开关**。规模实测（`editor.py build`）：3000 帧一次生成成功（155.4 s、`draft_content.json` 8.57 MB、`materials.videos=3000`，草稿≈2.86 KB/帧），未触上限；体积取决于内容熵——低熵合成帧 320×180 1,381 B/帧、1080p 15,181 B/帧，真实照片级 1080² 抠像帧 **1.87 MB/帧（25 fps ≈ 46.7 MiB/秒）**，离线抠像用本机 RMBG-1.4 量化 ONNX 在 CPU 上 **2.609 s/帧**。**不要承诺**：写笔划让剪映自算抠像（`matting` 键被计划契约拒、图片素材走 `matting_cache` 被 `kind=='video'` 门槛拒，两条都是构造性反证）、图片素材导出端与原生静帧一致。证据：`Skill维护层\来源\抠像素材化试点-20261016\`（含两张逐像素对照图与真实抠像产物）。

## 03 跟踪：输入契约已核对，后台计算仍暂存

原安装XML参考第6.13节要求区分source、follower及ready candidate：motion用中心框，surface用candidate来源平面的四角；四角不是跟随图层展示变换。没有ready candidate不猜ID/时间窗；主轨不能自跟踪。真实videoTracking只有单个pts或endTime==startTime是初始化失败，不是已计算。

先验证新任务与源范围，再核对帧覆盖，最后验目标跟随及遮挡恢复、保存重开关联。完整帧数与保存重开不能代替遮挡恢复质量；旧早停原因未定位时仍保留缺口。不能用手工路径替代原生跟踪或复用旧cache冒充新计算，契约审查也不等于当天重新计算。定位正常任务/事件/取消入口；受阻时继续可独立验证的参数项。

2026-10-16 离线路线实测结论（结论为「不可行」）：跟踪**没有可离线加载的模型**。此前被当作跟踪线索的 `Tracking.dll` 实为**应用埋点/事件日志模块**（24,152 条 ASCII 串里 `onnx` / `bytenn` / `opencv` / `Kalman` / `objectTracking` 各 0，`tracking` 152、`sqlite` 73，含 `INSERT INTO table_tracking_event …`，对应 `Tracking\tracking_v2.db` / `tracking_v4.db`），与视觉跟踪无关。真正的跟踪靠 `single_object_tracking_v1.0.model`(627,511 B) 与 `bingo_objectTracking_v1.0.dat`(163,884 B)，两者同样建不出会话；加载器线索集中在 `cccreator.dll`（`single_object_tracking`×4 / `bingo_objectTracking`×4）、`videoeditor.dll`、`lyra_cli_client.dll`（另含内嵌串 `"object_tracking_model_name": "single_object_tracking"`、`no usable mask artifact generated`）。草稿侧实测 48 份里 0 份出现 `tracking`、`materials.video_trackings` 全为空数组 ⇒ **轨迹出不来**，离线只能写跟踪的标签声明。证据同上目录。

## 04 原生缓动：图片两点水平smoothstep正式接入

先查真实序列化契约，避免使用XML注明忽略的easing/ease字段。把数学目标映射成原生类型和相对时间/值手柄；用独立透明图层、线性对照和相同取帧时刻测量实际运动，再改变时长、距离及方向复验。只看曲线图或关键帧数量不能证明插值生效。

原生类型、手柄和实际位置对照共同证明插值；保存重开与终点编辑须独立核对 root/timeline 的类型、手柄、UUID及数值，并规范化省略默认值。已有终点编辑证据不能扩成手柄UI编辑。

正式开放的子集与证据见 [原生缓动](capabilities.md#easing) 和 [局部复合](capabilities.md#composite)。扩展 verify 同时拒绝未请求曲线的手柄篡改，防止普通线性计划被静默改变；新子集的拒绝边界须覆盖非法输入、时间/手柄/身份及未请求曲线篡改。

后续研究要点：

- 曲线变速必须另外核对源/目标时间映射及音画同步，位置缓动不提供这份证据。
- 垂直位移按半画布高度换算且正值向上，不能复制水平像素尺度。
- 组缩放用颜色见证块和文字外框核位置与尺寸，再核编号视频源帧；不能把静态 clip 缩放单位或理论连续边界直接当成渲染后的明亮像素宽度。
- 起点缺层的静帧判失败；独立会话恢复不当作共享渲染已修复。
- UI 编辑重开、其他属性、多点、自定义手柄与视频其他组合仍须新证据。

## 04b 曲线变速：静音视频两至三点正式接入

原安装前端action、速度材料序列化和真正N-API参数分别核对，不把前端value直接套进N-API。先用有帧编号的全新静音视频建立基线，再检验两点、三点、非对称点与非零源入点。原安装模块15123在独立Node VM中提供期望时间映射；预览通过独占服务读取真正引擎帧，逐帧解码编号，数学推导与渲染证据分开。

时间映射、生成字段与 N-API 差异见 [曲线变速](capabilities.md#speed-curve)。N-API 更新曲线后标量 speed 可能残留之前的值，研究时以点、范围和实际帧核对。

当前开放的子集、窗口与组组合见 [曲线变速](capabilities.md#speed-curve) 及 [曲线视频与图片白字组](capabilities.md#speed-curve-groups)。每个新组合都独立准入：用仅窗口、仅组、固定速度与无组控制分别区分两条时基，再做独立正式重建；不能从各项分别通过推定组合通过。

组合验证的测量方法：

- 先测新画布下图片与字形的实际尺度，再决定字号；不按统一倍率盲目调整。
- 控制标记必须在全部采样状态可见；被裁掉的标记不能作为组中心证据。只看终点不证明缓动，要核四分之一、四分之三位置。
- 标记高度采用当前画布的原生实测可见基准，不把旧理论像素数当作新画布观测值。失败测量保留，只重分析已有帧，维持容差。
- 窗口测量曾混入上移白字：保留失败，只重分析既有帧，并用已知诊断源的安全内区同色底区分源与前景；不重复渲染、不放宽容差。专用检测规则不推广到任意素材。
- 复用已留的窗口/线性控制与源映射，避免同条件重渲染；旧控制不能提升为本批新帧，完全遮挡的内容不能宣称可见，完全遮挡的字形用前后完整显示和仅组控制核恢复。
- 新目标局部时刻若不在旧控制/映射采样中，另建独立见证与有限映射核验；同条件旧帧复用，不以相近时刻替代。
- 比较固定信息时分别测完整字形/标记、不透明面板内部和源安全区；信息条以外的源画面变化不算标签漂移。
- 曾按解码源偏移比例预测中间位置失败，实际指定采样与目标局部线性位置相符；端点映射、参数坐标与渲染插值分开核，不推广到其他动态属性。
- 含声音视频即使 volume=0 也不准入，不自动剥音绕过边界；曲线音画同步与有限动态矩形之外的源运动键继续研究。

离散静帧只证明源/目标映射，不证明连续播放、音画同步或UI保存重开。格式与复验命令见 [计划格式 · 曲线变速](plan-format.md#曲线变速) 与 [曲线变速](capabilities.md#speed-curve)。

后续研究按实际收益逐项选择，逐项保存结论；不把某次研究顺序当成自动接续授权。

## 12 静帧预览可靠性：时间戳之外要求合成稳定

原生播放器的 `seek`/`refreshCurrentFrame` 返回 accepted 且 VEF1 时间戳落在一帧容差内，仍可能只是合成层尚未刷新；同一会话的乱序采样曾保留上一位置的叠加层。研究用颜色切镜、移动面板和文字建立可判错控制稿，发现小图默认铺满画布会遮住背景，先修正测试构图再判断刷新。当前预览 worker 在每个请求中清空稳定计数，只有时间戳合格的RGBA像素连续三次完全一致才保存帧；普通轨与局部video/panel/captions复合各8个乱序/重复位置通过，源草稿未变且每个worker正常走受控退出。

该规则只提高320×180局部静帧的收帧可靠性；它不证明连续播放、高清边缘、音频监听、算法任务或导出。像素一致也不能替代实际查看画面：通过准入仍需看选中PNG，测试素材和预览目录留在工作区证据，临时worker输出结束后按清理回执处理。

## 05 字幕识别/逐词样式：识别链路与文字样式必须分开

先区分声音到时间文字的ASR与已有字幕的局部样式。11.5安装的`subtitle_track`是DraftEditing宏，按主轨绑定的MediaIndex ASR和字幕模板展开；运行时代码实际调用`MediaIndex`的`asr.transcribe`，标准profile为`asr.default`，时间单位为source微秒，版本标记为`word-sentence-v2`。没有宿主capability transport/token时，普通进程调用安装`lyra-cli`会得到`unauthorized host process`；登录账号不替代宿主授权，不能用手写字幕、离线猜词或普通文字轨宣称ASR完成。

已有字幕的重点词样式属于另一条链。XML层`rich_text_style + text.range`要求UTF-16半开区间；不能直接把它当成原始草稿`content.styles[].range`的全Unicode验证。中文样式可见不代表emoji等Unicode范围也正确。分别核对码点、UTF-16和实际内容styles范围，隔离字体fallback、颜色、字重及范围转换；加载accepted/退出0不能证明画面正确。静态样式不等于逐词时间识别。2026-10-19已新增 [同句重点词着色](capabilities.md#text-highlights) 的有界生产字段，以下原生Unicode失败仍作为历史边界，不能推广到emoji或动态逐词高亮。

2026-10-16 补一条**离线路线**证据（当时未接入 Skill 入口；2026-10-17 已作为正式入口接入，见本节后面的回填）：ASR 模型、词典与句切配置就在本机磁盘（`%LOCALAPPDATA%\JianyingPro\User Data\SupplysStore\local-asr-supplies\…`：encoder 385MB / punc 180MB / token 7832 行 / `strategy.json`），剪映自带的 `onnxruntime-node` 1.29.0 配本机 Node 22 可在**不联网、不装包、不取宿主 token**的前提下建会话并推理；按应用自己算出的特征反推定标后（16kHz、32ms 窗 / 10ms 帧移、自然对数能量、无 CMVN），36.014s 缓存音频解出 63 字可读中文（**没有**与剪映官方转写做过逐字比对——`离线ASR-20261016\README.md` 把「与官方逐字比对」明列为未验证项），重跑文本与 `ctc_probs` 逐字节一致（证据与失败变体表见 `Skill维护层\来源\离线ASR-20261016\`，Lead 已独立复现：63 字、`blankFrac=0.9289` 一致）。边界：特征配置是**推断值**（非官方实现）、切片语义未复现、标点模型 3 类映射未打通、近静音输入出 0 字。因此本节结论不变——**离线结果只能作素材理解参考**，不能当作字幕生产证据，也不得用手写、猜词或普通文字轨冒充 ASR 完成。

契约定位与离线样式实验未取得生产准入，原始失败样本留在项目。

**2026-10-17 回填**：宿主侧结论不变（`unauthorized host process`，官方 ASR 仍未接入）。离线侧另立了一条**正式支持入口**：`scripts/transcribe.py`（见 [离线转写](capabilities.md#transcription)）用 faster-whisper + 调用方自备的模型目录，在**不联网、不要宿主 token**的前提下把媒体转成逐段时间文本与 `字幕.srt`。它与上面的 Tools 层路线是两条实现：那条走剪映自带的 onnxruntime-node 与推断特征，这条走 CTranslate2 与公开权重，**都不是剪映官方 ASR**。准入的是「拿到逐段文字与段级时间」这件事：实测 15 s 中文素材 8 段 / 59 字 / 覆盖 0.000→15.000 s / RTF 约 0.07–0.10、重跑逐字节一致；文本为模型原样输出（不人工改写、不补标点），时间只有段级（`word_timestamps=False`），**未与官方智能字幕逐字比对**。因此仍不得把离线结果说成官方识别完成，也不得据此声称逐词样式或逐字时间。

2026-10-19 新增本地faster-whisper模型词级子集：显式word-timestamps产出原words与源SHA256，captions --level word可映射为独立文字段；已用真实本地模型和MCP到草稿链验证。它不改变上述宿主官方识别/局部样式边界，也不等于任意用户文稿强制对齐或逐字拆时。接口与拒绝规则见 [模型词级时间](capabilities.md#模型词级时间与独立文字段)。

## 06 分离/自动闪避：配置回读不能代替声音计算

分开核验新分离计算、已有stem绑定与BGM自动避让。11.5前端`audio.setVocalSeparation`接受segmentId/choice/timeRange/productionPath，写入vocal_separation材料；None=0、Background=1、Vocal=2。它不是计算入口。安装Lyra静态帮助列出`draft algo sound-separation --mode vocal|instrument`，但本机普通进程连`--help`也返回-100015/unauthorized host process，本轮未提交算法。会员登录不能替代宿主鉴权，不伪造token、宿主或产物路径。

空productionPath的set请求可能返回accepted却使目标消失；update/remove参数往返只证明配置语义，空path不产生新stem。研究对照用独立新会话/workspace避免修改态污染；往返测试则明确保持同一会话。具体请求失败只限定该输入，不推成全软件不支持分离。

自动闪避在本轮所查前端/运行时未定位可执行入口；不能扩大为全软件不存在。ASR词句时间、VAD讲话区间与音乐避让包络是不同输入/结果，不能互相冒充。已有可靠讲话区间时可用现有audio.keyframes规划BGM增益，但这是人工区间安排，不是新自动ducking能力。**2026-10-17 补**：离线侧已有正式入口 [离线自动闪避](capabilities.md#ducking) 的 `scripts/ducking.py`——它从人声 stem 算包络、写音量关键帧，属于音频分析 + 关键帧，不是剪映的自动 ducking，也不需要宿主 token。按固定速度的源时间映射设置，并考虑起落过渡、呼吸间隔、关键词可懂度、音乐抽吸与混音真峰值；数值检测不替代试听。

准入分离前须合法宿主入口、独立新语音与背景输入、实际新stem及源范围/声道/采样率身份、正确绑定、真实音频与试听证据，并区分算法取消与工作进程退出。双音合成输入仅作配置控制，不评价人声质量。宿主侧的分离与自动闪避继续暂存，不新增生产字段；离线侧的两个支持入口见本节回填。

**2026-10-17 回填**：上面的宿主侧结论不变（宿主 token 拿不到，算法入口仍不可用）。离线侧已另立支持入口：[离线人声分离](capabilities.md#separation) 的 `scripts/separate.py`（htdemucs ONNX + onnxruntime，模型与运行时由调用方自备，实测 CPU 约 1× 实时）与 [离线自动闪避](capabilities.md#ducking) 的包络脚本同期准入。两者都不经剪映运行时、不需要宿主 token，产物仍按普通素材/关键帧写进计划，界面播放与导出归用户。

## 07 调色扩展：静态RGB三点曲线正式接入

先核对真实color_curves的L/R/G/B锚点、控制柄、select_channel、资源与启用/蒙版归属，再以全新彩条和灰阶建基线，分别试升降、混合通道、L/HSL组合、局部区域与普通视频源范围。研究脚本直接修改材料的画面不能替代正式接口验收；生产准入须经过validate/build/verify/离线publish/交付链，并用不同参数重新生成独立原生帧。

当前开放的调色子集见 [调色](capabilities.md#grading)。原生单通道会耦合其他 RGB 像素，不用独立逐通道数学模型判错；回读精确核对材料，画面核对色偏、明暗、局部范围及内容目的。

跨片段取帧即使时间戳正确也可能有画面残留，须独立会话重新核验，不能记成共享工具已修复。

## 08 蒙版与合成：用途分类、真实裁区和源时间分别验收

先区分视频裁切与局部调色蒙版：资源存在、旧materials.masks、adjust分类或enable开关单独成立都不能证明裁切。用独立前景和高反差背景检查保留区/透明区/反转，核对common_mask、当前缓存、video分类、type与constant_material_id，再测位置、尺寸、旋转、源时间和复合局部区间。旧矩形成功不扩大为所有形状。

动画验收按源范围、帧量化容差与可辨的起中尾几何核对；近圆形主轴不稳定，旋转用明显椭圆的端点判断。静帧与 UI 编辑/保存重开、连续播放分别记录。当前准入见 [矩形](capabilities.md#mask-rect) 与 [圆形与椭圆](capabilities.md#mask-circle)。

正式链路须验证分类/资源/path/存储/引用/开关、关键帧时间/控制柄，以及局部复合嵌入、离线publish/sidecar与交付。篡改测试修改真正被引用的材料，外层未使用副本不代替权威组件数据。倒放需另验真实新逆序产物与源范围，不能只改速度符号。

蒙版复验的后续方法：静帧收帧改进后，先以完全相同的新输入隔离资源path，再核对几何/反转/动画和权威复合材料。矩形空 path 无裁切、同输入绑定已测缓存则裁切，这一发现已修正正式生成与回读。缓存源码里的羽化倍数和历史 sqrt 迁移不足以证明实际引擎转换及质量；羽化状态见 [参数兼容未准入](capabilities.md#param-only)。

## 09 倒放：绑定契约不等于逆序计算

11.5前端video.reverse接受segId/isReverse/reversePath；VIDEO_REVERSE绑定已有路径，播放源在reverse为真且路径非空时选择reverse_path，否则使用原路径。前端切换逻辑镜像源范围、效果范围、普通/锁定关键帧与曲线速度点，普通关键帧交换左右手柄并将X取负。它不是新视频逆序计算入口，也不能未经验证直接套成N-API语义。XML的matting.reverse和CLI抠像--reverse反转保留区域，reverse-sync是草稿回转XML，均不是时间倒放。

用全新编号素材建立正序基线，再以独立进程/会话对照空路径、无效目标和普通编辑。reverse=true空路径仍可正序播放；无效目标也可能accepted；原片充当reversePath只能是负对照，不能当作生成的逆序产物。false请求若改变源范围，先记录未解释的语义差异，不能用它作安全撤销。时间戳匹配甚至独立进程仍可能出现首帧残留；异常帧不作精确时间映射证据，先检查内容编号和稳定后续帧。

本机普通进程的Lyra帮助请求被宿主授权拒绝，所查范围未确认合法倒放计算入口；会员登录不解除该限制，也不证明全软件不支持。后台倒放继续暂存，不新增生产字段、不用负speed替代。旧UI新缓存成功与当前后台准入分别保存，已清理缓存不能再次绑定。

重启研究须有合法新计算入口或可复验的参数语义修复。先证明输入身份、源范围、真正新逆序文件及帧号递减，再核对带声输入的逆序音频、绑定、关键帧/效果/速度镜像和保存重开；提交、进度、算法取消与工作进程退出分别验证。只准入实测子集，不能用参数回读代替计算结果。

2026-10-19 离线替代路线已接入：统一 `reverse` 操作按有界选区生成新逆序源素材，具有原素材身份、逐帧/采样专项与普通草稿交付证据。上述宿主入口/原生开关仍暂存；它不镜像旧计划效果和关键帧。支持输入、限制及调用见 [离线短片段倒放](capabilities.md#离线短片段倒放)。

## 10 资源调用：身份、路径和字形分别验收

先拆字体、文字模板、贴纸、花字/发光、动画与预设，不给它们共用一份成功状态。资源枚举、通用InfoSticker配置和文件扩展名不足以确认类型：模板包内的字体是依赖，不自动准入为独立字体；字体须将后端名称/资源ID/effect_id/md5与真实文件对应。缓存目录由当前环境发现，只保存相对定位和身份，不把本机文件或账号缓存塞入Skill。

后端FontType会导出占位盘符；资源ID正确但路径占位/缺失，原生引擎可能静默回退默认字形。因此先用完全相同的文字、字号和布局建默认/真实路径/缺失路径对照，再实际看字形与字宽；MAE只说明变化，不能独自证明字体正确。正式接口对未准入名、缺缓存、字节/元数据变化及未请求的字体篡改直接拒绝，不让静默fallback成为生产成功。

当前子集见 [缓存字体](capabilities.md#font)。新字体须经过 validate/build/verify/离线 publish/sidecar/交付及独立原生静帧，不复用旧工程作生成结果；非 BMP 范围与未测字形覆盖不扩成全面 Unicode 支持。

文字模板和贴纸的安装XML要求真实MaterialRecall blueprint_ref或当前草稿真实ref，并保持模板多输入框/依赖及独立片段身份；静态说明不能当成已取得可执行ref。安装XML明确不支持原生文字发光属性，而运行时仍有text_glow类型；只能限定所查接口，不推成软件没有发光。描边/阴影不登记为原生glow成功，模板宿主或贴纸不能当普通视频随意套speed。文字模板、贴纸及其他发光包继续暂存，下一次须取得合法资源解析/完整本地包及独立原生呈现证据再接入，不猜ID、下载或复制旧模板冒充。

## 11 模板复用：来源、准入和局部重建分别判断

先从当前运行进程定位外部索引，再核实选中来源的文件/ZIP条目与哈希，最后检查来源和逐工程环境指纹。历史索引、旧通过数量或标题不证明当前可用；缺来源不能用独立控制模板替它准入。来源别名的root与登记保留旧证据规则见[模板方法](template-library.md#外部数据与检索)。

有当前片段准入后才显式映射新素材、文案、时间基准和运动模式，按原片段完整时长同比重建线性运动；用不同起点/时长的新计划经过正式build、独立回读和离线publish。核实新ID、源稿/基础计划不变、未选择的原资源有遗漏记录且未暗中迁移；错误目标、未知时间基准、缺替换素材和覆盖输出须拒绝。不凭复制目录或新名称宣称重建。

局部画面核验用独立会话采样可辨起中尾，按帧率与运动速度确定位置容差，同时检查换素材后的布局和文字。这些证据只覆盖实际控制输入/当前子集，不能升级为原库模板视觉通过、原缓动等价或整套复用。原库来源恢复后逐份重验；整套、UI编辑保存重开、连续视听和导出仍分别判断，不新增生产schema或替暂存效果放行。

文字发光研究另发现artistEffect目录中的TextBloom包；配置仅InfoSticker不够，须结合SDFText脚本、bloom参数定义和原安装序列化/绑定契约。绑定的材料可使引擎恢复发光位，关闭用无绑定对照。实际看文字本体是否完整，像素变化或光晕增加不能代替字形保留；默认字体偏置/多行失败时收窄到已测缓存字体单行。当前生产子集见 [放射发光](capabilities.md#glow)，不证明所有缓存模板或 XML 发光属性可用。运动扩展先独立核有光/无光运动、相同位置静态发光、白字完整及实际位置，再核原片阅读底叠加；缓动核四分之一/四分之三位置与线性不同和原生手柄，不能以终点相同证明缓动。

## 文字透明度的原生映射

2026-10-19已按 [GlobalAlpha子集](capabilities.md#text-global-alpha) 接入。REA对资源/alpha的宽查询仍有歧义，保留原始回执；缩小安装chunk后结合实际源码与原生旧Alpha/GlobalAlpha/TextAlpha对照，确认文字必须用专用GlobalAlpha。它不是普通视频alpha，也不是只改字面填色的TextAlpha；类型正确还须核字面/描边、局部时钟及同值静态原生控制。


## 角点透视补验

新角点先确认原生类型被执行，再将动态中间与末点保持帧同静态corner_pin_info控制比较；仅序列化成功不算运动。用已知四角色块与内外区域核几何，角标自身包围框不是投影角点。新三角点的有界准入统一见 [能力主表](capabilities.md#perspective)，不能从两个预设推广到任意坐标、多角运动或视频。


## 离线节拍入口回填

宿主节拍计算与原生音乐标记不因枚举存在而视为可用。离线librosa候选与显式按N拍重排主轨时长，现有独立 [受限入口](capabilities.md#beat-editing)；它验证样本时钟/素材身份/片段边界，不替代正常速度试听，也不从节拍密度推断音乐表达质量。
