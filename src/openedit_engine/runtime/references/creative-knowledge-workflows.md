# 可复用模板与工具地图

这些模板供 Agent 在任务需要时自行填写到项目已有分析或 notes，保留自主创作空间；不是要求用户预先填表，也不新增引擎计划字段。真实故事、声音、参考及用户反馈必须与来源和版本对应。

## 模板一：创作决策简记

```text
任务与观众：这次作品或片段要让人理解/感受什么；用户已选软件与不可忽略的要求。
素材证据：候选源区间、事件与声音；分别标已实际观看/试听、模型或转写线索、待核实。
结构与取舍：段落分别改变什么信息/关系；关键原因、行动和结果是否都有依据；可选结构为何取这一种。
声音与视觉：哪些对白/原声必须保留，BGM或留白怎样参与；关键镜头连接为何这样做。
不足与下一步：不能可靠确认或不能按当前后端实现的核心部分，以及当前可做的工作。
```

不适合剧情的任务可将“原因/行动/结果”替换为展示、信息或情绪变化。只有片段线索而缺关键剧情时，标为待查，不把猜测写成剧情事实。

## 模板二：一个关键连接的设计

```text
意图：观众从什么信息或情绪，转到什么新信息或情绪？
前镜：源范围、动作阶段、关注位置、需要保留的声音。
后镜：源范围、进入动作/构图、接管后的停留和作用。
连接：比较的两种实质不同方法；选中的镜头、图层、声音和可编辑操作。
对齐：各层源时钟、切入/退出、对白/音乐边界；是否重放同一源区间。
条件与验证：当前后端/素材前提；实际连续画面、实际音轨和仍待核实的部分。
```

**示例，仅为虚构素材**：先出现一只手递出物件，另一段不同时间的手接过另一物件；前后手的位置和动作阶段需通过连续画面确认。可以比较动作硬切与声音先入；如果并非同一事件，要让观众能辨认时间变化，不把两段剪成真实连续动作。示例不代表某个项目已拍到或已采用该方案。

## 模板三：反馈与短段对照

```text
反馈与对象：用户原话、版本和可定位范围；哪些部分已被明确认可。
问题判断：内容/信息、节奏、声音、视觉连接或技术异常；事实与推测分开。
比较：同一素材、音乐、目标和输出条件，只改变影响问题的关键决定；需要时做短段A/B。
观察：各版本的注意力交接、动作/对白完整、叙事变化、声音与画面干扰；给出具体位置与证据。
状态：技术通过、连续视听、用户认可、未验或失败分别记录；保留旧版与来源。
```

用户反馈“平淡”时先检查信息和情绪是否变化，再看节奏与视觉；用户反馈“不像剧情”时检查目标、障碍、选择和结果是否可辨认。既有被否定版本不是合格基线，也不代表每种技巧都无效。

## 工具与模板如何落地

下列为当前引擎公开操作名，不承诺每台机器的模型、缓存、资源或后端状态；参数以 `openedit <操作> --help` 和当前能力表为准。执行属于实际任务，查看本地图表或转写不自动授权上传素材、安装或付费。

| 需要解决的问题 | 可用入口 | 不能据此声称 |
|---|---|---|
| 查素材信息、切点候选或本地参考抽样 | `inspect`、`reference`（可选 `--detector pyscenedetect`） | 抽帧等于看完连续视频、听懂声音或还原高级转场 |
| 同素材方法实操对照 | `practice-compare`：两段明确选区和已有预览，记录目标、变量及来源哈希 | 文件生成等于同素材已自动核实、原生完整混音、实际观看或审美通过 |
| 找对白候选、试人声分离 | `transcribe`、`separate`；需调用方提供本地模型 | 转写已校对、分离已无损或模型一定已安装 |
| 歌曲事件候选与时间映射 | `beats`、`beat-apply` | 每拍必切或模型已听懂音乐 |
| 指定音视频的分析/成片审片 | `music-edit` 的 `prepare`、`analyze`、`review`；后两者按配置调用服务 | 授权可跨任务、素材分析等于成片审片、模型评语等于认可 |
| 音量避让 | `ducking`，使用符合前提的声音输入及计划 | 自动包络等于完整混音与试听 |
| 渲染可复用动效透明配方 | `render-overlay`、`overlays[].recipe`（见 [配方与映射](recipes.md)） | 静态 RGBA PNG 通过等于整段成片节奏或叠加审美合格 |
| 校验并构建开源时间轴工程 | `capabilities`、`validate`、`layout-tracks`、`build` | 工程构建或严格全解码通过等于完整连续视听审美通过 |
| 查看多帧合成预览与无头导出 | `preview`、`export`、`filmcraft-exec` | 离散预览静帧等于连续播放流畅；须结合导出播放核验 |
| 同一文本、字幕或对话 | `captions`、`graphics.newText` 与 Subtitle 烧录轨 | 机器转写、词级时间或歌词来源已人工核对 |

模板与配方是方法与参数的候选，先检查素材、源时间、图层职责和当前能力边界；缺少匹配配方时直接用 `overlays[].layers` 或多轨组合原创。用户项目、原始视频、完整工程、模型、缓存和个人偏好不打入可分发知识文件。可核对方法来源见 [来源与证据](creative-knowledge-sources.md)。

## 参考片分析与实操对照

`reference` 默认保留 FFmpeg 检测；`--detector pyscenedetect` 使用固定的 PySceneDetect 0.7.2 ContentDetector，`--content-threshold` 默认27，`--min-scene-seconds` 默认0.3。两种阈值不共用；结果只包含所选窗口内的切点候选、候选镜头区间、中位时长及每分钟切点数量，不能识别运镜、变速或特效。窗口两端可能截断镜头；抽帧、原声提取、VFR/精确帧及语义均须另核。强转场与运动可能漏检/误判，不根据检测不到就认定没有技巧。

本机已将 PySceneDetect 0.7.2 安装在 `%LOCALAPPDATA%/OpenEditEngine/optional/pyscenedetect-0.7.2`，只在显式选择该检测器时加载；它使用现有 `cv2`，不下载模型或发送素材。其他环境需自行提供该版本和一个可用的 OpenCV 发行包，以及其 click、numpy、platformdirs、tqdm 依赖；缺失时明确失败，默认 FFmpeg 不受影响。上游包声明依赖 `opencv-python`，与现有 contrib/headless 分发包可能覆盖同一个 cv2；不要让 pip 自动安装第二种 OpenCV。本机采用固定版本包仅安装到独立可选目录、`--no-deps`，复用已检依赖；可选目录不被共享环境的 `pip check` 管理，不能把该检查通过当作此可选包依赖全部合规的证明。来源与BSD许可见可选包的 dist-info/licenses/LICENSE 和 [PySceneDetect](https://github.com/Breakthrough/PySceneDetect)。

实际练习用可编辑 `.fcproj` 分别生成可观看的基础版及方法版（使用相同源/目标/音轨并明确修改变量）；已有两段视频时，用 `practice-compare --left 左视频 --right 右视频 --left-start 0 --right-start 0 --duration 9 --audio none --goal "要看的表达" --change "本次改变" --out 新目录` 生成对照。`--audio left|right` 明确选择一侧声音；不混两条音轨。输出并排审片及 `comparison.json`，包含输入哈希、窗口、左右侧、目标、变量和验证边界。允许两段不同输入，因此同素材、剧情和音乐一致性仍由执行者核查并记录；编码、解码和哈希不等于观看、听过或用户认可。正式 FilmCraft 工程和原素材不因对照工具而改变。该流程吸收 [video-agent](https://github.com/agamm/video-agent) 对可追溯选镜与回看的思路；不复用它的其他编辑器或 Apple Silicon 转写假设。
