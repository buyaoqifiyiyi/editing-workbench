# 剪辑创作决策层

本层负责把实际素材变成有依据的创作决定，在制作与修订中持续使用；[开源剪辑步骤](editing.md) 将这些决定映射到 **OpenEdit Engine** 的纯开源可编辑操作。对用户保持简短方向与关键取舍；详细源时码、连接依据、取舍和修订留在项目分析、`creative-brief.json`、`notes` 或 `剪辑交付.md`，不要求用户审核逐镜头表。

## 纯开源后端职责分工

OpenEdit Engine 采用纯开源多核协同架构，无商业版分辨率、时长、参数白名单或密文草稿限制：

- **FilmCraft（主剪辑 / 调色 / 字幕 / 导出）**：承接多轨 V/A 时间轴、硬切与转场、变速/倒放、Lumetri 曲线/色轮/HSL/LUT、26 种混合模式、富文本多色重点词高亮、图形与烧录字幕、OTIO/FCPXML 交换与 H.264/HEVC/ProRes 导出，产出可由桌面端直接打开微调的明文 `.fcproj` 工程。
- **EffectCraft（高级动效 / 特效 / 透明叠层）**：当仅用 FilmCraft 基础运动/调色不足以完成高级文字动画、图层样式、复杂遮罩、表达式或 3D 合成时，通过 `overlays[]` / `render-overlay` 固定渲染为 **ProRes 4444 RGBA (.mov, `yuva444p12le`)** 叠层并自动合入主时间轴，或通过 `effectcraft-exec` 直通调用。
- **FFmpeg 与离线 AI 工具（按需白名单辅助）**：`inspect`、`reference [--detector pyscenedetect]`、`normalize-media`、`music-structure`、`shot-search [--with-motion]`、`motion-analyze`、`sfx [--from-structure]` / `sfx-search`、`interpolate`、`depth`、`shader-fx`、`auto-cut` / `rough-cut` / `auto-reframe` / `matting` / `audio-master` / `beats` / `beat-apply [--use-downbeats]` / `ducking` / `transcribe` / `separate` / `denoise-audio` / `tracking` / `layout-tracks` 及 `audit` 仅按具体创作问题选用（不为了堆技术而强制启用）。

单独特效、调色或音频任务只处理相关部分，不强行建立完整主时间轴。

## 分流（唯一维护位置）

按创作要求是否明确分流，与是否新项目无关：

| 情况 | 做法 |
|---|---|
| 只有素材或笼统的“帮我剪一下”，且未授权自主决定 | 轻量查看实际素材，提供简短方向，等待用户选择 |
| 已给脚本、指定模仿视频，或明确了主题、表达、风格、结构等方向 | 保留已有要求，直接进入相关创作判断；细节自行决定，不追加方向选择 |
| 已选定方向或明确让 Agent 自主决定并直接剪 | 按下述流程自行取舍并执行，不增加确认 |
| 明确的局部修改 | 保留认可内容，只检查受影响的镜头、阅读、声音和相邻连接；不重剪全片 |
| 用户主动要求比较或重新考虑方向 | 按请求给选项，即使已有脚本或参考 |

用户只要建议或拆解时，以相应文本为终点，不创建工程、不执行 `build` / `export`。原请求包含制作时，方向确定后直接执行。执行中仅在三类情形询问用户：**核心目标互相冲突、不可替代素材缺失、或需要调用外部付费/外发服务（如用户自配云端 `music-edit analyze/review`、付费在线素材）**；服务地址或密钥已配置不等于当次任务的素材外发或费用已获授权。已授权自主剪辑时由当前 Agent 做相应创作取舍。

## 每版同时设计剧情与剪辑

每个制作版本同时形成并落实两条思路：**剧情思路**决定观众获知什么、人物关系或情绪怎样变化；**剪辑思路**决定用哪些镜头、切点、节奏、构图与声画关系让变化发生。第一版可以粗糙，两条思路都要在实际片段中可辨认；不能先拼完故事，再把剪辑表现留到下一版。非叙事作品对应内容组织与视听表达；只读分析与方向建议仍以文本为终点，不因本要求扩大授权。

**剪辑前先看同款作品。** 新建、整体重剪或需要重做表现时，在可访问的视频网站主动搜索与题材、片型、目标情绪和制作要求相近的作品（优先用户指定参考，再找同素材或相近目标的不同作品）。对能实际读取的参考视频挑选有代表性的连续片段拆看：叙事信息如何推进、镜头与景别怎样连接、节奏怎样起伏、构图与层次如何发展、声音如何参与；本地参考视频可配合 `openedit reference --detector pyscenedetect` 提取切点候选（仅给候选边界，不能代替观看运镜、变速与特效）。记录来源、实际观看范围与可核实观察；仅看到标题、封面、文字或字幕时标为线索，不称为看过剪辑或听过音乐；借鉴方法而不照搬作品、未经授权素材或虚构参数，区分参考片源运动与后期加工。项目内已有近期适用的已观看参考可复用；局部小修只查受影响内容，用户要求不联网时遵从，查找参考不授权外发用户素材或新增付费。

将上述参考观察与知识检索贯彻到以下 5 项动作中（沿用项目分析、`creative-brief.json` 或 `notes`，不另建强制表单）：

1. **选材与设计时一起决定**：关键段落将“信息或关系的变化”与“镜头怎样表达变化”配对，落到源范围、动作与反应、入出点、密度、观看重心、声音边界与前后接管；持续长镜头可以成立但要有保留依据，并将原片自带切镜/摄影运动/原声调度与本次新增剪辑选择分开判断。
2. **知识在决定前参与**：开工或重剪前先用 `search_knowledge` / `openedit knowledge` 检索剧情组织与剪辑表现两方面方法，按 [主动展开候选](../references/creative-knowledge-techniques.md#主动展开候选) 为关键段落比较通用剪法与实质不同的高级候选，再落到选材、切点与层序；仅阅读指南、列技巧名称或增加特效数量不算落实。
3. **制作中核对落实**：先用代表性段落及其前后文确认两条思路同时成立，再展开同类段落；若只改变片段排序，回到段落内部重做，不以补字幕、全场统一轻推横移或零散贴包装结清剪辑表达。
4. **每版分别验收**：内容推进与剪辑表现分别写明已实现、存在问题与尚未验证项，并指向实际时间范围与预览证据；发现关键表达缺失时先修正再交付。结构校验、`strict_decode` 与 `audit` 指标保留各自技术层级，不替代连续视听审美。
5. **反馈只更新被评价的部分**：用户认可剧情但否定剪辑时，保留认可的剧情骨架并重做镜头与声画表现，不记作整版认可也不默认推翻已认可剧情；局部修改只复查受影响段落与相邻接点。

## 创作判断流程

新建、整体重剪或收到创意问题时，从 [创作知识库](../references/creative-knowledge.md) 按具体问题经 `search_knowledge` / `openedit knowledge` 与 `read_guide` / `openedit guide` 取用相关章节并落实到具体决定。动漫、游戏情绪混剪与 MV 先读 [漫剪与节奏混剪](../references/styles/anime-mix.md#镜头与音乐如何共同推进)，其他片型按 [通用剪辑方法](../references/general-editing.md) 与对应类型分区展开；每步只留影响后续操作的判断，已有有效分析可复用。

### 1. 从连续素材确认事件

先粗筛、再对选中范围及切点前后精看。短素材用 `inspect` 查看流与多帧抽样；长片或 10-bit HEVC 等重型源片，可先提取关键帧轻代理并配合 `shot-search [--with-motion]` 缓存语义初筛与局部切点边界探测，再对命中候选选择性执行 `normalize-media` 转为 8-bit `yuv420p` 恒定帧率 CFR（防止 FilmCraft 对 Hi10P 报 `MEDIA UNREADABLE` 以及 VFR 声画漂移）。核查人物在做什么、注意力在哪里、动作怎样发起/接触/收束、反应由什么触发与原片内部切点。景别、视线、运动方向、主体位置、光色和物件是连接线索；文件名、单张截图或剧情常识不能代替连续镜头证据。

在项目分析或 `notes` 中保留选中源范围与观察依据，区分**画面事实、基于事实的推断与待核实项**；抽帧只支持构图，连续动作相位与声音分别核实，不能播放或监听时标清未核实项。

完成条件：主线画面能对应到真实源段，关键动作、人物关系与声音证据状态清楚；无原素材时只给条件性设计建议，不编镜头、台词或时码。

### 2. 建立有镜头依据的表达

用一句可执行主张说明观众将看到什么变化（例如“由两人的相互回应走向单人空镜”），再选支撑关系、变化与结尾的不同镜头。区分动作展示、关系推进、意象联想与纯视觉节奏，明确全片及各段主导驱动。已有脚本或参考时先落实其意图，不擅自改写用户明确内容。

从真实素材决定进入点、信息顺序、情绪转折与结束位置；段数、高潮、快慢和长度随内容产生。为主视觉建立有素材依据的色彩、形状、空间或文字体系（如 `motion-analyze --make-lut` + FilmCraft Lumetri、`overlays[].recipe` 与明确层级的图形字幕），并在呼应与转折处发展或对比。素材缺少必要因果或结果时调整结构并说明缺口，不用泛化文案补造剧情。

完成条件：关键段落各自改变了信息、关系或感受且能指出实际画面依据，相同作用的冗余镜头已有取舍。

### 3. 让声音与画面共同组织时间

音乐主导时先确定实际 BGM 版本及源段，识别乐句、音色/配器变化、停顿、重音与人声语义，再安排画面发展；按需使用 `music-structure`（下行拍/语义乐段/Drop）、`separate`（人声与伴奏分离）、`sfx --from-structure` / `sfx-search`（构建音效床或检索拟音）与 `ducking` / `audio-master --sidechain`（闪避与响度统一）。带演唱 MV 若需歌词/对白对齐，可结合分离后的人声轨做 `transcribe` 段级转写并核对人声 RMS 气口包络标定入出点，绝不直抄未经核对的平台 LRC 时码，也不硬造零时长词级切分。原声主导时先保留动作因果、完整对白口型与反应。具体策略见 [混剪声音策略](../references/styles/anime-mix.md#bgm-与原声并置)。

用户已指定 BGM 并要求自动匹配镜头/意境或卡点时，按 [原生视听与音乐编排](../references/music-edit.md) 核查当前专用配置与当次授权；就绪后只对已授权的明确源选区执行 `prepare` + `analyze` + `beats`/`music-structure` 动作锚点编译，未配置或未授权时如实报告缺口，**严禁用均匀每 N 拍切镜、纯文字推测或模板指南冒充内容匹配**。拍点与峰值只是候选，未试听前不写听感结论。

完成条件：主要段落与声音变化有可解释对应，镜头停留容纳必要动作、阅读与反应时间，未试听部分保持未核实标注。

### 4. 在关键连接处作选择

先说清“前镜让人看哪里 → 怎样交接 → 下一画面如何停稳或释放”，按 [从表达目标到画面连接](../references/general-editing.md#从表达目标到画面连接) 全面评估动作与方向、视线与反应、景别与空间、构图重心、时间意象及声音节奏。

**主动创造转场条件**：叙事联系不足时先重选或重排；含义成立但缺少天然视觉匹配时，主动使用技术建立连接——用裁切、位移和缩放构造视觉锚点，借助光流运动趋势（`shot-search --with-motion`、`motion-analyze`、`whip_transition`）接续动作方向与速度，用蒙版或 `matting` 前景构造物理遮挡，使用干净的 `shader-fx` 几何/光学过渡，或让下一镜提前以小窗/分屏进入并按精确源时钟（`s + d * v`）接管全屏。提前进入与接管时须核查前滚是否夹入原片内切点，保持主体可辨认，保护对白口型、起音及文字阅读时间，严格遵守用户的无重复要求；视觉包装不能补造因果。

关键接点比较 2–3 种实质不同的剪法（如动作中硬切 vs 切反应、图形/动势匹配 vs J/L 声音桥接、窗口接管 vs 保持动作）并择优落实；普通明确接点直接决定，不为每一刀写评审表。当用户要求丰富转场或反馈“观感改善但转场/表现仍偏少”时，审查全片的换景、时间跳转、情绪转折与景别变化，在仍直切或单调过渡的位置分段分配锚点匹配、运动延续、遮挡、光线与窗口接管变化，强变化后交还清楚主体并留出呼吸。连接是否改善观看与表现是否足够丰富分开评估，不设固定效果数量门槛。

完成条件：关键接点有观看重心与关系依据，选择已落到源入出点、顺序、停留、构图或声音边界，而非空洞技巧名称。

### 5. 把技巧变成适量且可执行的表现

从连接要解决的问题选择技法，不设固定“情绪→技巧”公式（悲伤≠自动叠化、高潮≠自动快切、重音≠自动震动），并以“无该效果的可行剪法”作必要对照；警惕大面积无目的推拉横移、缺乏信息增量的小画中画、遮挡脸部的贴字及堆砌关键帧/特效数量。需要丰富表现或排查“学了却没用”时，先查 [教程方法索引](../references/tutorial-library.md) 与 [纯开源手法映射与配方库](../references/recipes.md)，设计可感知的进入、发展、到位停留与下一镜接管，不能先铺满主轨再零散贴包装。

按纯开源能力与素材条件落实参数：

- **轨道与职责**：主剪辑、Lumetri 调色、遮罩、嵌套、多色高亮图形及烧录字幕使用 FilmCraft（有双语歌词/对白时在 `layer_order` 将字幕轨置于常规特效叠层上方）；高阶透明动效、表达式与真 3D 视差使用 EffectCraft `overlays[]`（13 套自适应/Hero 配方如 `whip_transition`、`impact_punch`、`parallax_3d_scene`，锁定 `ProRes 4444 RGBA`）。
- **AI 视效素材前提**：`matting` 须检查 `dropout_warning`、擦除与前景完整度；合入 `parallax_3d_scene` 等前景分离合成时，底景板应先剔除原主体/做浅景深洁净化处理并控制相机偏移防“双影重影”；`interpolate` 传入自定义 `--slow-factor` 时使用 `--model auto`（`rife-v4.6`）；`depth` 避开大面积镜面与玻璃反光镜次；`shader-fx`（如 `directionalwarp`、`radial`）须抽帧核对边界拉伸或接缝，优先选用边缘收敛稳定的预设（如 `crosszoom`、`dreamy_zoom`）。
- **整洁计划与安全轨道复用**：复杂段落可在项目内写 `creative-brief.json` 记录源范围、层职责与起止变化，执行计划 `edit-plan.json` 严格只写允许字段并以整微秒算术防浮点边界重叠；带显式 `layer_order` 的多轨计划可在 `build` 前按 [安全轨道复用](../references/plan-format.md#安全轨道复用) 运行 `openedit layout-tracks` 审阅映射，仅在方便用户在 GUI 微调且画面核查通过时采用新计划，不强求固定轨数，不改动用户已保存工程。

实现前区分直接可用、满足前提才可用与当前缺口，不可等价实现时如实说明，不静默删去核心要求。

完成条件：选中技巧具备表达作用、素材前提、严格字段路径与清晰的预期观看变化。

### 6. 用短段结果回看决定

初版优先检查代表性或高风险段落及前后接点。建议先以 `build --draft` 半分辨率快审，或先跑带 `--preview-times` 的 `build`（暂不急于全片 `export`）生成 `.fcproj` 与关键帧 PNG，重点核查注意力交接、动作/反应可读性、字幕安全区、Alpha 贴合、双影重影与着色器接缝；确认后再全分辨率 `export` 避免长片盲导返工。

交付前运行 `openedit audit --plan <edit-plan.json> --build-dir <build目录> --export <输出.mp4> [--beats <structure目录>] --contact-sheet --out <audit目录>` 一次性检查主轨源区间重复、成片及 `overlays/*.mov` 全流严格解码、EBU R128 响度与 0 削波、节拍/Drop 偏差与 `qc_contact_sheet.jpg` 联系表。

存在关键不确定性时，在同一源素材、同一 BGM 与同一目标下仅改变一个关键变量对比受影响短段（如接动作 vs 留反应、无效果 vs 锚点接管），并用 [practice-compare](../references/creative-knowledge-workflows.md#参考片分析与实操对照) 与 [短段比较与反馈积累](../references/creative-review.md#短段比较与反馈积累) 记录条件、结论与成对偏好案例。

若任务已获授权且外部视听 API 就绪，候选交付前按 [成片全模态审片](../references/music-edit.md#成片全模态审片) 对**当前版本带声音连续成片**运行 `music-edit review`，**调用与采信前必须核对画面与音轨各自版本哈希及时间段覆盖一致**，严禁拿早期素材 `analyze`、旧版音频或分段 HTTP 200 冒充全片声画验收；模型意见仅作按时间码核查工程的参考，不覆盖用户偏好。

完成条件：已发现问题已回溯至选段、顺序、声音、切点或表现修正；交付准确区分已核实层级与未验边界。

## 给用户的方向与交接

- **方向未定**：默认给出 **3 个**有实质差异的简短方向（素材只支撑 2 个时说明理由，用户指定数量时照办）；差异来自表达重心、组织顺序、节奏结构或声画主次，每项说明观众感受、大致做法与制约条件并推荐 1 个；未看过素材仅提供条件性建议，不编制作周期或效果保证。
- **参考视频边界**：先核实能否读取视频本身，区分“按此模仿”与“仅供了解素材”；封面、标题、评论与单帧抽样不能当作完整观片结果；仅有成片时，原作者轨道与具体参数只作待核实候选。
- **交接与修订**：复用项目已有分析、`creative-brief.json`、`notes` 与 `剪辑交付.md`，按实际需要记录中心主张、选中源段、声画转折、关键连接、技法取舍与未核实项，不另建强制表单。局部修订只复查受影响段落及相邻接点，已有足够证据时不再重复验证无变化部分。

## 交付与两类验收分离

向用户汇报成果时，务必明确区分以下两项，绝不将自动指标或结构通过表述为连续视听审美合格：

1. **内容与视听表达层面**：分别说明本版剧情推进思路与剪辑表现思路（选段取舍、切点/J-L-cut 声桥、转场与动效节制、调色与歌词/字幕分工），以及仍待用户主观看片确认的节奏、情绪或审美风险。
2. **技术验证层面**：分层列明实际执行的证据与范围（`validate` 结构校验、`build` / `export` 的 `ffmpeg -v error -xerror` 全解码、`preview` PNG 静帧视觉核查、`audit` 指标与 `qc_contact_sheet.jpg` 联系表、已授权时的 `music-edit review` 覆盖范围与画音版本一致状态），并提示使用者可随时打开 `.fcproj` 在 FilmCraft GUI 中进行主观精修与完整连续视听验收（`continuous_audiovisual_review` 由用户最终确认）。
